# 反馈分级规则定稿

## Question

把「反馈分级行动规则调研」的结果，落成运营循环每次「下一步」照着走的规则：读底表的哪些列、什么条件、给出什么动作（指向哪个方法 skill）、用中文怎么说给操作者听；以及证据闸的自查清单。

与操作者对谈（HITL）只问操作者能答的：「下一步」的说法看得懂吗、一次给一个动作还是给排序清单、多久看一次（每次开会话 / 每周）、动作需要你做的部分说清楚了吗。**不问行业判断**——条件与阈值以调研来源为准，没有来源的标〔未证实〕并取保守默认。

要定：

- 规则存放处（一份正典 reference，两条编排 skill 都引用；位置自定），格式便于 AI 逐条匹配底表。
- 冷启动段的规则（L0–L1 决策）；上移段若调研无阈值，写成「暂不决策，只记账」并留在地图 Not yet specified。
- 证据闸清单（执行前 AI 自查：每条说法有来源；〔未证实〕不写成事实；产品事实走事实源入口）。
- 反馈闸（执行后看 L1–L3）与「操作者只决定发不发 / 上不上」的衔接。

## 调研交接（「反馈分级行动规则调研」关票时写入）

- 依据文件：`wayfinder/closed-loop/research/feedback-action-rules.md`。规则表已按网页 / 邮件 / 询盘 / 冷启动→上移分节，每行有级别、信号、条件、动作、承接 skill、来源、适用前提，可直接作为规则文件的底稿。
- 大多数「比率类」情形调研结论是**无通用阈值 → 只记账**；定稿时不要为了让每行都有动作而补数字。可执行的只有技术阻断、退信状态码、标题 / 摘要缺陷清单三类。
- 调研未解、需在规则里写成保守默认或留 fog 的：无计划封数时的跟进次数与间隔（不代选 3–5 / 4–7）；收录后零展示多久算异常；询盘 >9 之后的起改线；休假自动回复后隔多久再发。
- 归因口径：一个锚点（一条登记 URL 或一条登记外展序列）的成败只数挂在它上面的询盘；未归因询盘仍计北极星。

## 完成标准

- 规则文件定稿；用底表原型里的样例数据人工走一遍，每种样例都能得出一个下一步。
