# 每日提醒

每天早上，电脑自动从 Google 取数写进底表，接着按反馈规则算出当天的「下一步」，送到三个地方：

| 送到哪 | 看到什么 |
| --- | --- |
| Mac「提醒事项」App，列表「de-linker 下一步」 | 一条提醒。标题就是当天要做的那件事，点开看「备注」是全文 |
| `日常账号` 的邮箱 | 一封信，主题是「de-linker 下一步 · 日期：要做的事」，正文和提醒备注一样 |
| 工作邮箱 `chester@de-linker.com` | 同一封信，留作工作记录 |

真实邮箱地址只写在仓外的配置文件和私有 vault 里，本页只写角色名。

## 什么时候到

- 08:30 开始取数（GSC 回流）。网址多的日子要 40 分钟左右；当天已经查过的网址不会重查。
- 取数一结束，紧接着算「下一步」并送出（算一次大约 40 秒）。所以一般在 09:10 前后到。
- Mac 当时在睡眠：醒来后补跑。关机的那天没有提醒。

## 提醒里写什么

正文的格式和你在对话里说「下一步」时看到的一样（规则文件 [`docs/feedback-rules.md`](feedback-rules.md) 第 11 节）：

- **下一步**：一件事，动词开头。
- **为什么**：底表里的依据，写明哪张表、哪个网址、哪天、什么状态。
- **你要做的**：具体到点哪里；没有就写「不用你动手」。
- **你要决定**：发不发、上不上；没有就写「不用你决定」。
- **AI 会做的**：AI 接下来做什么，用哪个方法。
- **做完以后**：要不要告诉 AI、要等什么。
- **还在排队的**：最多列 5 件，其余只报数。
- **只在记账的**、**在等的**：不用动、只在等的事。

末尾还有一段「两条线现在在哪」，抄的是营销、获客两张台账的阶段。提醒只看底表里的反馈；你开会话说「下一步」时，冷启动阶段会先做阶段工作，只有 P1、P2 的反馈才插队。所以两边说的可能不一样，这是正常的。

几种特殊的日子：

| 标题 | 意思 |
| --- | --- |
| 下一步：今天没有要动的 | 反馈都只是在等，正文写在等什么 |
| 今天取数出错｜下一步：…… | 今天的取数没跑完。「下一步」按底表里最近一次成功的数据算（看正文末尾「底表数据」那一行的日期），正文附上出错的日志 |
| 今天没算出下一步 | 算的时候出错了（没网、表格读不到……），正文写着出错原因。开会话说「下一步」，AI 会再试一次 |

前一天自动建的提醒，如果你还没勾掉，第二天会被自动勾掉，因为当天的新提醒已经取代了它；没做完的事会在新提醒里再出现。你自己在这个列表里手动加的提醒不会被动。

## 看状态、关掉、重装

在「终端」里，进到本仓库目录后：

```sh
uv run scripts/gsc_pull.py schedule status    # 定时装没装、上次退出码、日志最后几行
uv run scripts/gsc_pull.py schedule remove    # 关掉：取数和提醒一起停
uv run scripts/gsc_pull.py schedule install   # 重新装上（每天 08:30）
uv run scripts/daily_reminder.py run --dry-run   # 只把今天的提醒打印出来看，不送
```

日志在 `~/Library/Logs/de-linker-playbook/gsc-pull.log`：取数和提醒写在同一个文件里，提醒的行以「每日提醒：」开头。上次退出码不是 0，说明取数或提醒有一样出了问题，日志里写着是哪一样。

## 用到的配置（都在两个仓库之外）

- `~/.config/de-linker-playbook/config.toml` 的 `[reminder]` 段：收件人、发信服务器、发信账号、授权码文件在哪。
- `~/.config/de-linker-playbook/qq-smtp-auth-code`：QQ 邮箱的授权码（权限 600）。要换授权码：在 QQ 邮箱「账号与安全 → 安全设置 → 授权码管理」删掉旧的、生成新的，用文本编辑把新码存到这个文件、覆盖旧的。
- 「提醒事项」的授权：第一次运行时 macOS 弹框，点了「好」。在「系统设置 → 隐私与安全性 → 自动化」里能看到、也能收回。
