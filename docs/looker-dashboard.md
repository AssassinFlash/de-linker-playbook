# Looker Studio 看板搭建指南

本指南原为初次搭建指南；正式「De-linker 运营看板」已由 agent 于 2026-10-19 建成，链接在私有 vault。现在这份文档用于维护、复建和排查。目标是一屏看清：L0–L3 反馈、动作进度、最近执行登记、页面收录和搜索表现。看板只读「底表」；它不写回数据，也不替代 AI 的「下一步」判断。

> 正式核心看板已验收。网页表现与搜索词当时为空；等 GSC 出数后，由「看板表现面板补验」单独核验。

## 开始前

### 你要看懂的三件事

1. **一个 Google Sheets 数据源只连一个工作表。** 所以「执行登记」「网页表现」等工作表要分别添加成数据源。
2. **不要写死行数或 A1:U68 这类范围。** 选择工作表标签，让连接器随底表自动扩行。
3. **时区不同。** 执行登记、动作进度、询盘等时刻是北京时间；「网页表现」和「搜索词」的日期按 Google 的太平洋时间切日。

## 第 2 步：添加 6 个数据源

**这一步在干什么：** Looker Studio 的 Google Sheets 连接器一次只连一张工作表。把看板需要的 6 张数据表分别接进来。

依次添加以下工作表，数据源名称保持和工作表名完全一致：

1. `执行登记`
2. `网页收录`
3. `网页表现`
4. `搜索词`
5. `询盘`
6. `动作进度`

每添加一张，都按同一套动作做：

1. 在报表编辑器里打开 **Add data / 添加数据**。
2. 选择 **Create new data source / 创建新数据源**。
3. 选择 **Google Sheets** 连接器，授权使用 `所有者账号`。
4. 选中「底表」这本表格。
5. **Worksheet / 工作表** 选择上表中的一张工作表标签；不要改用自定义范围。
6. 确认 **Use first row as headers / 首行作为表头** 已勾选。
7. 点 **Connect / 连接**，再点 **Add to report / 添加到报表**。
8. 回到资源面板，把数据源名称改成该工作表名。

**截图位 2：** 六个数据源名称在资源面板中排成一列；不要截到底表链接或 ID。

### Agent 参照稿发现的实际坑（2026-10-19）

- 当前产品横幅写「Looker Studio 现已更名为数据洞察」，部分按钮即使界面语言是中文也可能显示英文（例如 **Add to report / 添加到报告**）。这是同一产品的命名变化，不是走错页面。
- 正式底表的「网页表现」「搜索词」当前 0 行。agent 实测：Google Sheets 数据源虽能连接这两张空工作表，但字段面板可能暂时只出现 `Record Count`，看不到 `日期（太平洋时间）`、`国家`、`设备`、`搜索类型` 等列。这是本次参照稿的实际观察，不是官方文档承诺的行为。
- 遇到这种情况不要硬点，也不要往正式表写假数据。第二屏可先用「底表（样例）」的对应工作表搭出版面、趋势和筛选控件；等 GSC 首次写出真实行后，回到数据源刷新字段，再把图表数据源从样例切回正式「底表」。正式「询盘」表若也没有数据行，按「L3 版面维护」同样处理：先用样例数据源配字段，再切回；禁止向正式表写假数据。
- agent 参照稿链接和整屏截图只记私有 vault `marketing/00-system/looker-dashboard.md`；公开文档不复制链接。

## 第 3 步：检查字段类型

**这一步在干什么：** 字段类型错了，日期趋势、去重计数和汇总都会失效。这里只改 Looker 的字段解释，不改 Google 表格。

在 `动作进度` 数据源里创建一个计算字段：

| 字段名 | 公式 | 用途 |
| --- | --- | --- |
| `动作数` | `COUNT_DISTINCT(登记编号)` | L0–L3 scorecard |

在 `询盘` 数据源里创建：

| 字段名 | 公式 | 用途 |
| --- | --- | --- |
| `询盘数` | `COUNT_DISTINCT(询盘内部编号)` | 询盘总数 |

再逐个数据源检查类型：

| 字段 | 类型 |
| --- | --- |
| `执行日期`、`检查日期`、`日期（太平洋时间）` | Date / 日期 |
| `登记时刻（北京时间）`、`写入时刻（北京时间）`、`更新时刻（北京时间）` | Date & Time / 日期时间 |
| `展示`、`点击`、`近 7 天展示`、`近 7 天点击` | Number / 数字，聚合 SUM |
| `点击率`、`平均排名` | Number / 数字 |
| `登记编号`、`网址`、`搜索词`、`国家`、`设备`、`搜索类型` | Text / 文本 |
| `询盘内部编号` | Number / 数字，仅用于去重 |
| `创建时刻（北京时间）`、`形式发票签发时刻（北京时间）` | Date & Time / 日期时间。只在 Looker 里改字段类型，不改底表 |

**截图位 3：** `动作数` 与 `询盘数` 字段已创建，类型为 Number。

## 第 4 步：搭第一屏「今日总览」

**这一步在干什么：** 第一屏回答“现在做了多少、走到哪一级、最近发生了什么”。

把页面命名为 **今日总览**。顶部放标题文字：`De-linker 运营看板 · 今日总览`。标题下放一行说明：`L0 已执行 → L1 已到达 → L2 有互动 → L3 有转化；询盘只含形式发票申请。`

### 4.1 五个数字卡

用 **Scorecard** 添加 5 张数字卡，横向排一行：

| 数字卡 | 数据源 | 指标 | 过滤条件 | 标题 |
| --- | --- | --- | --- | --- |
| 1 | `动作进度` | `动作数` | 无 | `L0 已执行动作` |
| 2 | `动作进度` | `动作数` | `当前最高级别` 属于 `L1`、`L2`、`L3` | `已到达 L1` |
| 3 | `动作进度` | `动作数` | `当前最高级别` 属于 `L2`、`L3` | `已互动 L2` |
| 4 | `动作进度` | `动作数` | `当前最高级别` 为 `L3` | `已转化 L3` |
| 5 | `询盘` | `询盘数` | 无 | `形式发票询盘总数` |

这些 L1/L2/L3 是累计口径：一个动作到了 L2，也会被算进“已到达 L1”。在每个数字卡下面加一行小字：`L1/L2/L3 为累计口径`。

**截图位 4：** 五张数字卡在同一行，数字和标题清楚可读。

### 4.2 动作进度表

**这一步在干什么：** 让你一眼看到每个动作现在走到哪一级。

添加一个 **Table / 表格**：

- 数据源：`动作进度`
- 维度：`执行日期`、`登记编号`、`线`、`渠道`、`动作大类`、`动作`、`网址或收件公司`
- 维度继续放：`查证结果`、`当前最高级别`、`收录状态`、`和上次比`
- 指标：`近 7 天展示`、`近 7 天点击`、`归因询盘数`
- 排序：`执行日期` 倒序；第二排序 `登记编号` 倒序
- 行数 / 分页：每页 20 行
- 标题：`动作进度（最新 20 条）`

**截图位 5：** 动作进度表在第一屏下半部，不用横向滚动也能看到 `当前最高级别` 和 `收录状态`。

### 4.3 最近执行登记

**这一步在干什么：** 每天先确认最近一次动作是什么，作为归因锚点。

再添加一个表格：

- 数据源：`执行登记`
- 维度：`登记时刻（北京时间）`、`登记编号`、`线`、`渠道`、`动作大类`、`动作`、`内容说明`、`网址`、`收件公司`、`查证结果`
- 不要放：`邮件 Message-ID`、`查证证据`、`备注`
- 排序：`登记时刻（北京时间）` 倒序
- 行数：5 行
- 标题：`最近 5 条执行登记`

**截图位 6：** 最近执行登记表显示 5 行，操作者能直接读出最近一次动作。

### 5.3 页面收录与表现表

**这一步在干什么：** 把最新收录状态和累计搜索表现放到同一行，逐个页面检查。

先创建一个 blend，命名为 **页面收录与表现**：

1. 打开 **Resource / 资源** → **Manage blends / 管理 blend** → 新建。
2. 表 A 选 `网页收录`，重命名为 `收录状态`：
   - 维度：`网址`、`收录状态`
   - 指标：`检查日期`，聚合设为 MAX，显示名改成 `最新检查日期`
3. 表 B 选 `网页表现`，重命名为 `搜索表现`：
   - 维度：`网址`
   - 指标：`展示` SUM；`点击` SUM
4. Join 字段：左边 `网址` = 右边 `网址`。
5. Join 类型选 **Left outer / 左连接**，以收录状态为主，保留尚无表现的页面。
6. 保存 blend。

用这个 blend 添加表格：

- 维度：`网址`、`收录状态`
- 指标：`最新检查日期`、`展示`、`点击`
- 排序：`最新检查日期` 倒序，第二排序 `展示` 倒序
- 标题：`页面收录与表现（按网址与状态汇总）`

如果某个网址历史上从“未收录”变成“已收录”，表里可能出现两行状态。读数规则写在表格旁：**看 `最新检查日期` 最大的那行，就是当前状态。**

**截图位 9：** 页面表的字段面板或表格标题，能看到 blend 名称和左连接设置。

## L3 版面维护

**这一步在干什么：** 询盘回流写进正式底表之后，在已经建成的报表上补上 L3 能看的明细和趋势。不新建报表，也不另建对照报表。

正式报表仍是 `所有者账号` 名下的 **De-linker 运营看板**。链接只在私有 vault，本页不写。页 1「今日总览」上的「形式发票询盘总数」已经在，不要重做。只扩展页 2「趋势与页面」底部原来的 L3 留位。

1. 用 `所有者账号` 打开已有报表，进入编辑。

### 正式表还没有行

- 禁止向正式底表写入假数据，也不要在 Looker 里手填数字冒充回流结果。
- 可临时把「底表（样例）」的「询盘」工作表加成数据源，只用它把上面的明细表、趋势图和字段类型配出来。样例全是假数据，图表标题或旁边注明「配置用样例，尚未切回」。
- 正式表有真实行之后：打开正式 `询盘` 数据源，刷新字段；把这两张图的数据源从样例切回正式底表；去掉「配置用样例」字样。
- 切回之前，不要把还指向样例的报表当成当天的 L3 读数。

## 常见卡点

| 卡点 | 怎么处理 |
| --- | --- |
| 找不到底表 | 只回私有 vault `deliverables/marketing/00-system/base-table.md` 找链接；不要问公开文档。 |
| 数据源里没有中文表头 | 确认选的是正确工作表，并勾选“首行作为表头”。 |

| 日期不能做趋势 | 日期字段改为 Date；询盘的创建 / 签发时刻保持 Date & Time。 |

## 邮件版面维护

**这一步在干什么：** 邮箱回流写进正式底表之后，在已经建成的报表页 2 替换邮件留位。不新建报表，也不另建对照报表。

1. 用所有者账号打开已有报表，进入编辑。
2. 新增数据源，选正式底表的工作表 `邮件反馈`。不要改用自定义范围，不要写死行数。
3. 把页 2 底部原来的邮件留位文本换成下面三块，仍留在页 2，不另起一页。
4. 旁边留一句：`未见退信是推断，不是投递回执。表里没有正文和地址。每日提醒不进这张表。`

明细表：

- 维度：`事件日期`、`登记编号`、`收件公司`、`事件类型`、`反馈级别`、`退信状态码`、`回复分类`
- 不要加回信正文、收件地址。`回信 Message-ID` 可以进表，但不要拿它做标题。
- 排序：`事件日期` 倒序
- 标题：`邮件反馈`

事件分布：

- 维度：`事件类型`
- 指标：`记录数` COUNT
- 图：甜甜圈或柱状图
- 标题：`邮件事件`

级别：

- 维度：`反馈级别`
- 指标：`记录数` COUNT
- 图：柱状图
- 标题：`邮件走到哪一级`

当前可以为空。保留数据源和字段，不要写死行数，也不要放示例公司。
