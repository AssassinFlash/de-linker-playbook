## 收集

### 可见度查询意图

用 Apify 搜索查证，覆盖下列意图至少凑满 10 条可记录测试。每条记下：query、平台、日期、本域 appears（Y/N 或缺口）、位次（有则写）、引用 URL、竞品是否出现、摘录、source。

1. best + 品类 + manufacturer
2. where to buy custom + 品类
3. 品类 + supplier + 目标市场
4. 品类 vs 替代方案 + for + 上下文中的商业场景
5. recommend a B2B supplier for + 品类
6. top + 品类 + companies in + 产地
7. 品类 + buyer guide + 当前年
8. how to choose a + 品类 + supplier
9. 品类 + price per unit + 目标市场
10. 品类 + OEM ODM factory

平台行分开记，不要把一次搜索同时算进三个引擎。

### 被引页面查询

再查至少 5 条，用于找回答引擎当前引用的页面类型：

1. 品类 + supplier recommendation
2. 品类 + buyer guide
3. best + 品类 + quality comparison
4. 品类 + factory review
5. 品类 + project case study

每条记录被引 URL、页类型、可被引特征（深度、权威信号、结构化数据、形态）。

### 公开检索与 Overview

对品类、品类 + supplier、品类 vs 替代方案，核验公开检索是否出现 AI Overview 或等价摘要框。有则记下摘要是否含本品牌、引用了哪些 URL。无 Overview 写「本查询无 Overview」，不算失败。

方法综述类查询（如何出现在回答引擎、结构化数据与实体做法）只在需要刷新机制时各查 1–2 条，不计入上述 10 条品牌测试。

### 竞品

对手名单优先取 `deliverables/marketing/01-foundation/` 已有竞品稿；没有则用 Apify 搜索查证品类 + 目标市场的公开供应商域。至少 5 个域名：

- 上述查询中是否出现
- 被引的是哪一页
- 被引形态（指南、对比、FAQ、产品页、目录、媒体）

需要原文时抓取指定 URL 的正文。用户已配置网页采集服务时，才用它抓公开页或动态页。未配置则只记录已抓到的 URL。

### 下限

硬门（达不到就写缺口，不降格成猜测）：

- ≥10 条可见度测试，覆盖至少两个可核验平台
- ≥5 个竞品域名的出现与否，带 URL 或显式缺口
- ≥5 个当前被引页面 URL（品类查询，不限本域）
- 实体三项：品牌名、产地、品类，各至少一次「搜索品牌或品类 + 产地」的记录

尽力项（有则写，无则缺口，不阻塞终稿）：

- 第三个回答引擎的实测
- 本站已有 schema 的抓取摘录
- 目标渠道资料页是否被引

### 核验

- 每条「appears = Y」必须能指回本轮搜索或已抓取正文的摘录。
- 可见度分数只由已记录测试计算，禁止口算一个整数交差。
- 竞品出现必须核验，禁止「该品类头部品牌一定会被引」。
- 内容缺口必须引用「竞品出现、本域未出现」的具体 query。

## 分析

### 平台信号

| 平台类型 | 查询类型 | 可见信号 |
| --- | --- | --- |
| 可检索的引用来源引擎 | 供应商、对比、选型指南 | 答案中的引用、来源面板 URL |
| 对话式回答引擎 | recommend a supplier | 回复中的品牌提及；打不开则缺口 |
| 公开 AI Overview | 信息 + 商业查询 | 摘要框片段与引用 URL |

### 可见度评分（0–100）

只根据已记录测试打一档，并在主稿写清计入的测试条数：

- 0–20：任何已测平台都无引用或提及
- 21–40：仅品牌词 1–2 条出现
- 41–60：部分通用品类查询被引
- 61–80：多条商业意图查询被引
- 81–100：主品类查询的首选引用

无法测试的平台不记 0 分、不记满分，从分母剔除并在缺口写明。

### 引用缺口

对每条「竞品出现、本域未出现」的查询写：

- 竞品被引页 URL
- 可被引特征
- 本站应对等的页（已有则写现状，无则写待建）
- 目标 URL 模式：有站点蓝图则对齐，无则只写模式并标缺口

### 实体

AI 回答依赖实体关联。分别测：

- 品牌名是否被识别为实体
- 产地是否与品牌同时出现
- 品类子类与关键能力是否挂到该实体

缺哪条关联，就在实体清单写对应内容或第三方提及动作。

### 内容形态

品类查询里实际被引的形态优先于想象中的形态。常见且可核对的包括：

- 长文选型指南（结构化小标题，直接回答段）
- 对比表（产品、材料或做法、供应商）
- 与真实查询对齐的 FAQ
- 带数据的文章（价格区间、交期、起订量；无公开数则不编）
- 第三方提及（目录、行业文章、行业媒体、目标渠道资料页）
- 程序化页：仅当含独特规格、图片与询盘入口

### 按角色排优先级

用产品上下文已有角色裁剪，不在本文件发明职业名单。查询类型与内容形态对照：

| 查询类型 | 内容形态 |
| --- | --- |
| 定制、表面或规格组合 | 规格对比指南、带参数的图库 |
| 交期、起订量、批量 | 进口与物流 FAQ、交期与定价说明 |
| 场景或项目类型 | 应用指南、项目案例（仅上下文已有） |
| 批发、产地、OEM | 规格页、合作说明 |
| 小单、在线购买、公开价 | 带清晰规格的产品页、小单 FAQ |

角色栏空着的行不要填进交付物。

### 结构化数据与站点蓝图

对照 `deliverables/marketing/02-seo/` 已有站点蓝图与 JSON-LD 计划（没有则缺口）：

- 优先核 Product、Organization、FAQPage、BreadcrumbList 是否已出现在已抓取正文
- 每条 AI 内容机会映射到枢纽/辐条 URL
- 每种 schema 写目标页 URL 模式与实现方式（JSON-LD / 模板字段 / 技术栈限制）

目标站点技术栈以产品上下文为准。不能输出 JSON-LD 的栈：写限制与替代，不假装已排期。

## 交付

全部写到 `deliverables/marketing/02-seo/`。策略与分析用简体中文。面客句子、URL、字段名、文件名按产品上下文；本仓库文件名保持英文。

### 主策略稿

`ai-seo.md` 六节每条建议都引用采集记录：

1. AI 可见度现状诊断 — 各平台实测 Y/N 或缺口
2. 竞品 AI 可见度对比 — 出现与否、被引页
3. 内容缺口分析 — 缺可被引页的具体查询
4. 优化行动计划 — P0 / P1 / P2；目标查询、平台、形态、URL、工时、source
5. 结构化数据建议 — 类型 + 目标页 + 实现方式
6. 实体建设路径 — 目录、报道、第三方提及、目标渠道资料页

### 表

`ai-visibility-report.xlsx`：从仓库 `templates/ai-visibility-report.xlsx` 复制后填。不能写表时改同目录 JSON，字段一致。两表合计不少于 20 行。每行 `source` 非空。

**AI Visibility Audit**

```
query, ai_platform, appears, position, citation_url, competitor_appears, notes, source
```

`appears` 仅用 `Y` / `N` / `gap`。`ai_platform` 写实际测到的平台名，未测不留空行充数。

**Optimization Actions**

```
action, priority, target_page, expected_impact, effort_days, status, source
```

`priority` 仅用 `P0` / `P1` / `P2`。`status` 默认 `planned`。`effort_days` 必须是数字或显式缺口，禁止「很快」。

优化行动至少 20 条；可与内容缺口一一对应，但 schema 与实体动作也要占行，不要 20 条全是「写一篇博客」。

## 缺口

- **打不开某回答引擎**：该平台全部记 `gap`，评分分母剔除，主稿写原因。禁止用另外一个引擎的结果冒充。
- **站点未上线**：可测竞品与被引页，本域 appears 一律 `gap`；仍可出实体与内容计划，须标明「上线后复测」。
- **无站点蓝图**：URL 只写模式，不发明已存在路径。
- **无公开价格**：价格类查询仍测可见度，正文不编单价。
- **Apify 修复与替代取证后仍不可得**：停止整轮采集，不写分数。

终稿禁止占位 URL，禁止把未核验字段写成事实。缺的只进缺口栏。
