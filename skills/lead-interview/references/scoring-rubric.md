## 怎么打

每轮用户回答后，按 0.0–1.0 重评全部四维。同一信息量打同一分，不因 skill 而忽高忽低。

分数看**已经拿到的信息**，不看用户自信。产品上下文里的事实计入 PMF，即使用户这轮没再说一遍。已有上游交付物自动计入上游语境。

## 产品-市场匹配（权重 35%）

对本 skill 而言，产品与市场的对应是否清楚到能产出高质量结果。

| 分 | 标准 |
| --- | --- |
| 0.0 | 没有产品或市场信息 |
| 0.2 | 只知名，无规格、无市场语境 |
| 0.4 | 有品类/规格，市场有名字但未刻画 |
| 0.6 | 规格与应用清楚，细分已列出但未排优先级 |
| 0.8 | 能力清楚，细分已排序，竞争位置有草图 |
| 1.0 | 哪些特性解决谁的哪类需求、为什么选他们，都清楚 |

按 skill 微调：

- `lead-icp-analysis`：偏应用场景和买家与产品的关系
- `lead-company-research`：偏哪些规格会改变选公司的标准
- `lead-competitor-analysis`：偏差异化和定位
- `lead-market-analysis`：偏规模指标和增长驱动

## 范围与约束（权重 25%）

这一次执行的边界是否清楚。

| 分 | 标准 |
| --- | --- |
| 0.0 | 没有范围，「全都做」 |
| 0.2 | 只点了目标地区 |
| 0.4 | 地理 + 行业有了，没有规模/类型过滤 |
| 0.6 | 纳入和部分排除清楚，边界情况未定义 |
| 0.8 | 纳入、排除、过滤、优先级都有 |
| 1.0 | 什么在内、什么在外、边界怎么处理，都能执行 |

按 skill 微调：

- `lead-company-research`：员工数上下限、已知 vs 新兴、地理过滤
- `lead-distributor-research`：规模、区域、品类匹配
- `lead-contact-discovery`：职位、资历、部门
- `lead-search-term-expansion`：平台、语言、搜索引擎

## 成功标准（权重 25%）

产出能不能对照具体期望验收。

| 分 | 标准 |
| --- | --- |
| 0.0 | 没有期望 |
| 0.2 | 期望含糊：只要「一些好的」，无数量或质量门槛 |
| 0.4 | 产出类型和数量已定，质量门槛未定 |
| 0.6 | 类型已定，且点名了关键质量指标 |
| 0.8 | 有可检查的成功度量：数量、深度、必有字段、一票否决 |
| 1.0 | 能写成验收句：满足 X/Y/Z 为过，出现 A/B/C 为不过 |

按 skill 微调：

- `lead-icp-analysis`：痛点具体程度、策略是否可区分、来源条数
- `lead-company-research`：域名能否验证、采购行为深度、公司数量
- `lead-market-analysis`：板块覆盖、数据新旧、增长率是否交叉验证

## 上游语境（权重 15%）

已有上游对这一 skill 是否够用、是否解释对。

| 分 | 标准 |
| --- | --- |
| 0.0 | 硬依赖的上游不存在（依赖检查本应拦住） |
| 0.2 | 上游在磁盘上，但未读或已过期 |
| 0.4 | 读过，但怎么用到本 skill 不清楚 |
| 0.6 | 内容懂了，先用哪一段未定 |
| 0.8 | 哪段上游喂哪块产出，映射清楚 |
| 1.0 | 映射、优先级、冲突都已处理 |

特例：

- 无硬上游的 skill（如 `lead-icp-analysis`）：产品上下文存在则上游维从 0.6 起
- 多个上游：按**最弱**的一条打分

## 加权

```
clarity = pmf × 0.35 + scope × 0.25 + criteria × 0.25 + upstream × 0.15
ambiguity = 1 - clarity
```

门槛：清晰度 ≥ 0.80（歧义 ≤ 0.20）。未达门槛不得打开目标方法 skill，除非用户确认 `user_waiver` 或已触达 15 轮硬顶。

## 打分纪律

- 关键项上用户说「不知道」：该维保持当前分，不罚也不抬
- 用户与产品上下文矛盾：当面确认，不默默覆盖
- 预打分只依据已读材料；提问循环里新确认的事实才能加分
