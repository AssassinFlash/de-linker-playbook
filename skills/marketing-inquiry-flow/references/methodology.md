## 输入

先读台账 `product_context`（缺省 `~/Documents/New/CONTEXT.md`；需要参数再读同目录 `fact-base/`）。上游若已存在则读：

- `deliverables/marketing/01-foundation/` 定位、买家角色、贸易条款
- `deliverables/marketing/05-cro/landing-page.md` 页面级转化发现
- 定价与样品政策（若已在 `01-foundation/` 或用户本轮给出）

再列出（未知则记缺口，不编造）：

- 询盘量、首次回复时长、询盘→报价、询盘→样品、样品→订单、主要流失阶段
- 团队人数、工时、语种、已用渠道、CRM 或表格

产品事实不写进 skill，不另写公司档案。品类、目标市场、产地只引用产品上下文对应字段，不在本文填值。

缺项列缺口后停。用户只给站点 URL、上下文仍缺品类或市场：抓该站能核实的事实后停，不进入落盘装成已完成。

## 采集

默认一条能力：用网页搜索查证。需要原文时抓取指定 URL 的正文。搜索不可用则停止并写缺口，不编造、不并列多引擎菜单。

### 本站询盘体验

抓取并摘录：

1. 首页 — 主 CTA 位置、文案、可选渠道
2. 产品 / 品类页 — 报价、即时通讯、RFQ 入口
3. 询盘 / 联系页 — 字段、必填/选填、布局、信任信号、CTA 文案
4. 下单流程或 How to Order 页（有则抓，无则记缺口）— 承诺步骤与时效

字段数与 CTA 原文必须来自已抓取正文。

### 竞品询盘入口（≥4）

每个竞品记录：必填字段名与数量、CTA 原文、回复承诺原文（无则「未声明」）、即时通讯是否出现及位置、移动端首屏是否有 CTA、来源 URL。页面不可访问则记下原因并换下一个，不编造。

### 查询意图

把产品上下文的品类与目标市场代入下列意图，每条记下 URL、摘录、访问日期：

1. 该品类 B2B 询盘流程优化做法
2. 外贸 RFQ 回复时效与转化的公开基准
3. B2B 制造网站询盘表最佳实践
4. 表单 / 邮件 / 即时通讯的首次回复处理
5. 制造询盘资质评分模型
6. B2B RFQ 询盘转化优化

结果不够时再补：回复时效案例、跟进节奏、样品政策公开页。仍用同一条搜索能力。

多页抓取需要隔离时 dispatch a subagent, else do it inline。

### 最低数据量

进入分析前至少备齐；达不到的写入缺口，不降低后项装成已完成。

- 本站：首页、产品页、询盘页已完整分析；流程页有则分析、无则缺口
- **4** 个竞品询盘入口：字段、CTA、回复承诺、渠道
- **3** 条外贸询盘优化做法来源
- **1** 条把回复时效与转化联系起来的基准（标「行业参考值，实际以你的数据为准」）
- 用户漏斗指标已采集，或显式写「用户数据未知」

### 校验

- 字段数与 CTA 来自已抓取页面，不靠记忆
- 转化率、回复时长有来源；行业数字必须带「行业参考值，实际以你的数据为准」
- 禁止编造统计、竞品 URL 或未抓取页面的字段清单
- `source` 必须含可访问 URL，禁止只写能力名

## 分析

### 漏斗

把每条发现映射到下列阶段（入口名称以产品上下文已出现渠道为准，不默认某一平台）：

```
站点访问 / 目录浏览 / 展会
        ↓
产品浏览（目录、图库、规格）
        ↓
首次接触（表单 / 即时通讯 / 邮件 / RFQ）
        ↓
首次回复 — 方法默认目标：工作时间内 2 小时
        ↓
资质判定与报价
        ↓
样品提议 → 样品发出
        ↓
样品认可 → 大货谈判
        ↓
大货确认 → 复购
```

### 摩擦维度

对每个已出现渠道回答：

| 维度 | 要回答的问题 |
| --- | --- |
| 入口摩擦 | 必填几项？移动端是否可填？CTA 是否在首屏？ |
| 渠道覆盖 | 产品页是否露出即时通讯或报价入口？邮件 / RFQ 是否可找到？ |
| 回复速度 | 相对 2 小时目标；非工作时间自动回复质量 |
| 回复质量 | 是否点名具体产品？是否只问 1–2 个聚焦问题？ |
| 资质 | 是否分层？热询盘是否不同路由？ |
| 样品桥 | 是否主动提议样品？政策与价格是否清楚？ |
| 跟进 | 停滞询盘是否有系统回收？ |

### 缺口方向

只根据已采集证据标缺口，不把未观察项写成已覆盖：

- 入口：产品页无报价、表单过深、即时通讯未露出（仅当目标市场需要时）
- 回复基础设施：无统一收件、报价路由慢、非工作时间无覆盖
- 资质：所有询盘同等处理
- 样品桥：无主动提议、价格或交期不清
- 跟进节奏：无停滞回收

### 资质评分

每条询盘按下列标准打 1–5 分。品类匹配与地理优先级对照产品上下文对应字段，不在 skill 里填值。

| 标准 | 信号 |
| --- | --- |
| 预算匹配 | 提到预算、问 MOQ、提到过往采购 |
| 时间线 | 给出具体交货或安装日期 |
| 项目类型 | 可核验的商业项目 vs 随意打听 |
| 决策权 | 决策人 vs 代为询价 |
| 地理 | 落在产品上下文的目标市场优先级内 |
| 具体程度 | 给出规格、数量 vs 空的「多少钱」 |
| 产品匹配 | 所询品类落在产品上下文能力内 |

档位与处理：

- Hot（22–30）：当日详细报价
- Warm（13–21）：2 小时内回复 + 针对性问题
- Cool（6–12）：目录回复
- Low（<6）：简短回复，不优先跟进

### 分角色首次回复

角色以产品上下文为准。上下文出现的角色必须覆盖；未出现的不要编造。下表是方法默认方向，不是客群清单：

| 角色方向 | 首次回复角度 |
| --- | --- |
| 采购经理 | 规格、MOQ、交期、贸易条款 |
| 项目承包商 | 交期可靠性、到货、MOQ |
| 指定人 / 建筑师 | 技术规格、认证、图纸支持 |
| 区域经销商 | MOQ 弹性、供货稳定、合作条款 |
| 渠道采购 | 快速报价、图库、小单政策 |
| 质量 / 合规 | 认证、检测、质检流程 |

每封首次回复：点名对方所询产品、给 1 个可核验的下一步、只问 1–2 个缺口信息。

### 样品桥接

必须写出：

- 触发时机（按漏斗阶段与角色档位）
- 样品价格或运费规则、交期
- 至少 3 个跟进节点（发出前确认、在途、收到后反馈）

## 交付

根目录：`deliverables/marketing/05-cro/`。每条对外建议引用采集来源 URL。

### 主文档

`inquiry-flow.md`：

1. **询盘流程现状评估** — 阶段 × 渠道矩阵、当前转化（未知则标明）、主要流失阶段；至少引用 3 个本站不同页面 URL
2. **竞品询盘入口对比** — ≥4 家：字段、CTA 原文、回复承诺、渠道
3. **摩擦点优先级排序** — 按漏斗影响，P0 / P1 / P2
4. **渠道覆盖优化方案** — 只写产品上下文已出现的渠道；每种给入口位置、字段或话术、路由
5. **首次回复框架** — 按角色 × 渠道的模板要点
6. **询盘资质评分系统** — 七维、四档、处理规则
7. **样品转化桥接** — 时机、政策、跟进节奏
8. **KPI 追踪计划** — 指标、量法、目标、回顾频率；行业目标须标注参考值
9. **行动清单** — P0 必做 / P1 建议 / P2 可选，并指向执行附件

已有该文件则增量更新，文首保留版本说明。

### 工作簿

复制 `templates/inquiry-flow-optimization.xlsx` 为 `inquiry-flow-optimization.xlsx`。禁止只交空模板。每行 `source` 非空。模板自带 Steps、Forms：按已有列名填，并保证 `Source` 为 URL。方法所需的三张分析表若模板没有则新建。不能写表时改 `inquiry-flow-data.json`，数组对应下表，字段同列名。品类、市场、所在地从产品上下文填写，不留 `{{...}}`。

| Sheet | 最少行 | 列 |
| --- | --- | --- |
| Steps（模板已有） | 按已抓取步骤逐行 | Step, Field, Required, Friction, Drop-off %, Recommendation, Priority, Source |
| Forms（模板已有） | 按已抓取表单逐行 | Form Name, Fields, Completion %, Avg Time, Mobile Score, Source |
| Funnel Analysis | 7 | stage, current_conversion_pct, benchmark_pct, gap_pct, primary_friction, priority_fixes, source |
| Flow Improvements | 10 | improvement, funnel_stage, channel, current_state, proposed_state, expected_lift, effort_days, priority, source |
| Competitor Benchmark | 4 | competitor_url, required_fields, cta_copy, response_promise, messaging_present, mobile_above_fold, source |

填写约束：

- Steps 的 `Drop-off %`、Forms 的 `Completion %` / `Avg Time` 无用户数据则空并在缺口说明，禁止填估计值冒充实测
- `current_conversion_pct` 无用户数据则空并在缺口说明，禁止填估计值冒充实测
- `benchmark_pct` 必须带来源，并在主文档标行业参考值
- `expected_lift` 无来源则写「未验证」，禁止编造百分点
- `cta_copy`、`response_promise` 用页面原文；无承诺写「未声明」
- `messaging_present`、`mobile_above_fold` 来自已抓取页
- `priority`：P0 / P1 / P2
- `source` 必须含可访问 URL

模板已有列名时以模板为准，并保证含 `source`。

## 反模式

1. 套用试用开通、套餐升级、激活等 SaaS 漏斗话术。
2. 不抓本站与竞品页面就给修改建议。
3. 忽略目标市场已出现的即时通讯或邮件主渠道。
4. 编造转化基准或回复时长。
5. 「简化表单」却不列出具体字段变更。
6. 所有角色共用同一封回复。
7. 跳过样品桥接。
8. 任何交付物行的 `source` 为空。

## 质量闸门

- [ ] 本站首页 + 产品页 + 询盘页已抓取；现状评估 ≥3 个不同页面 URL
- [ ] ≥4 个竞品入口含字段数、CTA 原文、回复承诺
- [ ] 每条建议引用采集来源 URL；未引用建议不超过总数的 5%
- [ ] 评分覆盖产品上下文相关角色
- [ ] 渠道方案只覆盖产品上下文已出现频道，缺的写缺口
- [ ] 样品时机与政策按阶段和角色写明
- [ ] 工作簿三表达到最低行数；每行有带 URL 的 `source`
- [ ] 终稿无试用/套餐/激活话术，无未替换占位符
- [ ] 行业基准均标注「行业参考值，实际以你的数据为准」

## 可验证断言

交付物文末写 5–10 条。评审可用下列形状核对：

1. `inquiry-flow.md` 现状评估引用 ≥3 个本站不同页面 URL
2. 竞品对照 ≥4 行，每行有 `required_fields` 数量、CTA 原文、回复承诺或「未声明」
3. Funnel Analysis ≥7 行、Flow Improvements ≥10 行、Competitor Benchmark ≥4 行，每行非空 `source`
4. 首次回复覆盖 ≥ 产品上下文角色数（上下文不足 5 个则覆盖全部已出现角色，并标明暂用方向），且 ≥3 个已出现渠道
5. 样品桥接含触发时机、价格或运费/交期、≥3 个跟进节点
6. 资质评分含 7 维与 Hot / Warm / Cool / Low 分数区间及处理规则
7. 终稿不存在未替换的 `{{...}}` 占位
8. SaaS 术语（free trial、premium plan、activation）出现次数为 0
9. 行业基准均带「行业参考值，实际以你的数据为准」；未标注不超过 1 处
10. 引用 URL 抽查可访问；抽 20% 时成功比例应 ≥80%，否则把失败 URL 列入缺口
