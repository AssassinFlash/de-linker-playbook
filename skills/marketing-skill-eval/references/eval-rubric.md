## 总则

- 每维 0–100。综合分 = 加权和。
- 任一维低于 40 → 报告标「需重建」，本轮仍只点名最弱维。
- 综合分不低于 70 → 通过；不低于 80 可视为收敛。
- 无证据不打分。

## Search Depth — 15%

问：调研步骤是否给出够具体、够数量的查证形状？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | 查询是可执行字符串；含品类/市场/年份等字段名；数量达到协议表 90+ 档 |
| B | 70–89 | 有查询形状，数量在 70 档 |
| C | 50–69 | 「用 Apify 搜索查证」但无可填字段 |
| F | 0–49 | 无调研步骤，或只有「做竞品研究」 |

FAIL 信号：零查询；查询里写死某个产品名而不指路上下文；工具 ID。

## Data Gates — 10%

问：最低数据是否能量化，缺了是否知道停？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | 门槛带数字（条数/URL 数/行数）；不达标写补采或停；关键声明要来源、日期；价格类要双源 |
| B | 70–89 | 有门槛，缺处理或缺时效 |
| C | 50–69 | 「尽量多收集」 |
| F | 0–49 | 无门槛 |

衡量：列出 skill 声称要交付的事实，检查是否规定「没有来源就不写」。价格/趋势若出现，是否要求采集日期。双源只要求关键数字，不要求每句。

FAIL 信号：「据统计」无出处；精确百分比无实验；缺数据仍要求写满表。

## Specificity — 15%

问：不读产品上下文，这份 skill 能否假装跑完？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | 步骤点名读台账 `product_context`；查询与产出绑定其中字段；正文无锁死的产品/城市/SKU |
| B | 70–89 | B2B 外贸口吻（询盘、MOQ、交期、规格）但未强制读上下文 |
| C | 50–69 | 任意制造业可直接套 |
| F | 0–49 | 通用增长黑客；或正文写死单一产品线 |

一票否决：paywall / signup / freemium / 免费试用主 CTA → ≤40。

FAIL 信号：面客数字写在 skill 里；渠道名写死且当唯一渠道；把 SaaS 注册流当询盘流。

## Beginner Clarity — 20%

问：零经验能否照做？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | 每步五要素齐：动作、能力、输入、成功、失败 |
| B | 70–89 | 步骤清楚，但默认会用某类后台 |
| C | 50–69 | 要另搜才能懂下一步 |
| F | 0–49 | 只有策略口号 |

衡量：抽 3 步 × 5 要素。能力名用「用 Apify 搜索查证 / 抓取指定 URL / 读本仓库相对路径」，不用 harness ID。

FAIL 信号：「优化页面」不说改哪、怎么算成；「调出价」不说依据哪条指标。

## Brilliance — 15%

问：是否超出公开博客共识？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | 跨行业借鉴 + 有依据的反常识 + 小团队不对称 + 第一性原理，四类里至少三类 |
| B | 70–89 | 有行业深度，不是模板句 |
| C | 50–69 | 扎实最佳实践 |
| F | 0–49 | 随处可搜到的清单 |

子分（各 0–25，和为该维）：跨行业、反常识、不对称、第一性原理。模式库见 `brilliance-patterns.md`。

FAIL 信号：每条都是「行业共识」；不区分小团队与大厂打法。

## Anti-Pattern Depth — 10%

问：失败模式是否可操作、是否独有？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | ≥8 条；含预算/停手/禁止编造之外的该 skill 专属坑 |
| B | 70–89 | 5–7 条，部分具体 |
| C | 50–69 | 有「易错」但像通用清单 |
| F | 0–49 | 没有，或只有「不要编造」 |

FAIL 信号：与兄弟 skill 易错节逐句相同。

## Teaching Value — 10%

问：读完是否懂 WHY？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | 核心建议都有底层原因 |
| B | 70–89 | 大部分有理由 |
| C | 50–69 | 零散「因为」 |
| F | 0–49 | 纯指令 |

衡量：有原理解释的核心步骤 ÷ 核心步骤数。

## Deliverable Spec — 5%

问：别人能否按同一路径交出可验收文件？

| 等级 | 分数 | 标准 |
| --- | --- | --- |
| A | 90–100 | `deliverables/marketing/` 或 `deliverables/lead/` 路径；字段名；min_rows 或等价完成条件；`source` |
| B | 70–89 | 有路径与字段，缺 min_rows |
| C | 50–69 | 只给标题 |
| F | 0–49 | 「输出一份策略」 |

FAIL 信号：仓外绝对路径；产出根不是 `deliverables/`。
