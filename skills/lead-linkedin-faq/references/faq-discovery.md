## 什么算 FAQ

买家在询盘或审厂前会反复问、且能用公开政策或流程答完的 **事实问题**。不是情绪顾虑、不是谣言、不是选购教程。

| 帖型 | 本 skill | 应改走（文件存在时） |
| --- | --- | --- |
| 事实政策 / 流程 | 是 | — |
| 情绪顾虑、怕踩坑 | 否 | `skills/lead-linkedin-buyer-concern/SKILL.md` |
| 行业误区要拆穿 | 否 | `skills/lead-linkedin-mythbust/SKILL.md` |
| 怎么选、怎么用 | 否 | `skills/lead-linkedin-education/SKILL.md` |

丢掉「听起来专业但没人问」的教育题。

## 事实问题领域

从这些领域收窄，不另造第七类营销题。本轮或 ICP 已点名的领域优先。领域名是分类；问句须换成产品上下文中的品类与政策，不得把本表当正文。

| 领域 | 问句必须问清的内容 |
| --- | --- |
| MOQ | 该品类的最低订量 |
| 交期 | 从定金到可出货要预留多久 |
| 样品 | 是否提供样品及条件 |
| 付款 | 首单可用的付款条件 |
| 质检 | 跨批次如何保持一致性 |
| 包装 / 运输损伤 | 如何包装以降低途损 |
| 定制边界 | 哪些尺寸或表面可定制、标准款停在哪里 |

问句必须像买家开口，不写成卖方卖点标题。

## 怎么找

按序用已有材料，缺的再搜，不编造：

1. 已批准 ICP 里的采购标准、异议、常见问题场景
2. 用户本轮给出的「经常被问到」领域
3. 已批准话题研究里偏政策 / 流程的话题
4. 产品上下文或产品知识里已经写明的公开政策（有政策才配得出答案）

每条候选写：买家属问句、一句建议答案或 `[待补充]`、证据（上游文件或本轮）。目标 2–3 条。用户已指定 1 条则不必凑满。

## 查证

默认用网页搜索查证；需要原文则抓取指定 URL。不并列引擎。禁止为凑次数空搜。

查询形状（花括号是字段）：

```
"[product_niche]" frequently asked questions buyers
What questions do international buyers ask when sourcing [product_niche]
"[product_niche]" [faq_topic] best practices standards
```

有用：采购指南、行业协会、买家论坛里反复出现的同一问句；可核验的标准名或流程名。噪声：软文标题、把关切或教程伪装成 FAQ。

答案里的标准、认证、流程必须能指回产品上下文、本轮或已抓取页。搜不到或搜索不可用 → 不把该标准写进公开答案，缺口写明；不编新 FAQ。

搜到的帖只作「有人问这个」的证据，禁止把原文写入交付物。

## 入选

- 本轮能问：只问一句选哪条。
- 不能问或用户说直接做：选证据最足、且已有可公开答案的一条；抬头写 `faq_confirmed_by_user: no`。
- 三条都没有可公开答案 → 停，只要一项：用户或上下文给出的公开政策。不编造 MOQ / 交期 / 付款来凑帖。
