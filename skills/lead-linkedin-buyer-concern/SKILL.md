# LinkedIn 买家顾虑帖（Structure 9）

用两步工作流写出共情优先的买家顾虑帖：先核验海外买家的真实犹豫，再按 Structure 9 成稿，落到 `deliverables/lead/08-linkedin/`。缺证据标缺口，不编造顾虑、流程或统计。本 skill 只产帖稿。

## 步骤

1. **共用规则与帖规范**。读 `skills/marketing-playbook-standards/SKILL.md`。读 `skills/lead-generation/references/linkedin-post-guidelines.md`（篇幅、钩子、CTA、标签、四种风格、软广）。完成：能复述数据锚定、例子禁引用、产出根、工具写能力，以及规范里的出门项。禁止把规范全文抄进本 skill 或交付物。

2. **输入**。读台账 `state/status.md` 的 `product_context`（默认 `~/Documents/New/CONTEXT.md`；把 `~` 展开为主目录，不当相对路径）。需要参数再读 `~/Documents/New/fact-base/`。硬依赖：已批准的 `deliverables/lead/01-icp/icp-analysis.md`。软依赖存在则读：`deliverables/lead/05-usp/usp-strategy.md`、`deliverables/lead/05-usp/product-knowledge.md`、`deliverables/lead/08-linkedin/topic-research.md`。用户本轮给出的品类、目标海外受众/市场、已知顾虑、公司应对流程、证明点、CTA 一并用，来源记「用户本轮」。品类、受众或市场仍不清时，打开 `skills/lead-interview/SKILL.md`（存在则按其做）；不存在则把缺口写入台账，不在本文件另写问卷。完成：能指出品类、受众、市场、供应地各依据哪几条；原文不拷进本仓库。硬依赖文件缺失、用户本轮也未给出对等全文、且无 `user_waiver` → 停。

3. **查证并列出候选**。用网页搜索查证该类买家向新的或远程供应商采购时，会卡住信任的真实犹豫；需要原文则抓取指定 URL。查询用品类、受众、目标市场、供应地（均取上下文，不预设出口国），意图覆盖买家顾虑、进口犹豫、首单信任、沟通与物流焦虑。搜到可核验顾虑即可，不凑搜索次数。搜索不可用：只采用 ICP 或用户本轮已说的顾虑，并写缺口；一条已核验的都没有 → 停，不编造。每条候选必须是**信任犹豫**（品质恐惧、沟通缺口、运输焦虑、定金犹豫、样品不符、首单信任、供应商可靠性），不是揭谣对象、不是运营痛点、不是事实问答。完成：2–3 条彼此不同的具体顾虑，每条有来源（ICP / 用户本轮 / URL）；不足 2 条则按实有条数写，少的在缺口写明，不补假顾虑。

4. **锁定顾虑与方案证据**。用户本轮已点名一条具体顾虑 → 跳过候选选择，仍须确认该条已在步骤 3 核验。未点名：本轮能问则只问选哪条；用户已说直接做、或本轮不能问 → 取证据最强的一条，交付物写明「顾虑未经用户确认」。然后只收上下文、USP、产品知识或用户本轮里**已经存在**的应对流程/政策/服务，以及可选证明点（认证、检测方法、担保、统计）。完成：入选顾虑一句、方案能写出具体步骤或责任点、CTA 类型已定；流程写不出 → 停并写缺口，不编造质检或交期承诺。

5. **按 Structure 9 起草**。帖子正文按「写法」六段一次写完，顺序不得调换。先共情后方案。面客语种以产品上下文为准（缺省英语）；策略笔记用本轮语言（缺省中文）；同一段不混用。标签 3–5 个，放在 CTA 之后，组合按已读的帖规范。用户点名四种风格之一时，按帖规范只改语气与结构，不改顾虑与方案事实。多 ICP 需隔离时 dispatch a subagent, else do it inline。完成：一篇可复制英文帖（除非用户指定其他面客语种）；六段都在；钩子落在规范要求的折叠前；证明点无则 Proof 段只写已核验流程，不补数字。

6. **质检并落盘**。对照本文件清单与已读帖规范出门项自检后，写入 `deliverables/lead/08-linkedin/buyer-concern-post.md`。发布由用户自行发布，或经用户已配置的工具发布；未要求发布或未配置 → `publish_status: copy_only`，不发送。付费发布须先告知并获准。完成：主文件非空；含候选、入选理由、完整帖、结构标注、来源、搜索日志、缺口；教学例子原文零出现。验证—审查—审批走 `skills/lead-generation/references/orchestration-protocol.md`，本 skill 不代替审批、不代替发布。

## 写法

Structure 9（顺序固定）：

1. **Hook**：直接点出这条顾虑，目标区域已知则可点区域；开场类型必须落在已读帖规范的钩子清单里。
2. **Acknowledgment**：1–2 句承认海外买家有此犹豫是正常的。
3. **Validation**：用一两句说明风险为何成立，证明你懂对方在赌什么。
4. **Solution**：写公司**具体**流程、政策或服务，步骤或责任点可核对。
5. **Proof**：有证据才写认证、检测方法、担保或统计；没有证据就停在已核验流程，不写空承诺。
6. **CTA**：全文恰好一个，用用户指定的动作；未指定则从帖规范的 CTA 类型里选一个接到本条顾虑。

共情优先：先让读者觉得被听懂，再给方案。承认顾虑合理，再写应对；不把风险说成「极少发生」来打发。

方案测试：读完能复述你们实际怎么做。写不出步骤或责任点，就还不是方案。

证明测试：证明点能指回上下文或 URL。承诺大于证据则删承诺。

软广、篇幅、段长、标签组合、四种风格：以已读帖规范为准，不在本文件重复。

输入写「品质不稳定、时差难沟通」。候选应写成可核验的具体犹豫（批次一致性、跨时区响应），每条能指回 ICP、用户本轮或 URL，不要写成「我们品质很好所以别担心」。成稿先承认顾虑合理、再说明风险为何存在、再写上下文里已有的检测或值班流程；没有通过率就不写通过率。CTA 用一句可答的经验问题或「DM me for [具体材料]」。不要把本节句子粘进交付物。

## 易错

- 没读 ICP 或没查证就发明顾虑。
- 把揭谣、运营痛点或 FAQ 当成顾虑帖。
- 先推方案再敷衍一句「理解你的担心」。
- 用「别担心 / 很少发生」打发风险。
- 方案停在「我们很重视品质」，没有可核对的流程。
- 编造认证、通过率、批次量或担保。
- 把产品特性伪装成买家顾虑。
- 承诺上下文里做不到的交期或赔偿。
- 忽略目标市场的商务习惯选词。
- 把帖规范全文抄进交付物，或把教学例子当正文。
- 未要求发布仍去发帖，或把成稿当成已发布。
- 终稿残留未解释的占位符。
