## 输入

读这些（存在才读，不复制进本仓库）：

- 事实源入口 `docs/fact-sources.md`（按其「什么问题查哪个源」取证；查不到标〔未证实〕）
- 已有 `deliverables/marketing/01-foundation/product-positioning.md` 与 `positioning-data.xlsx` / `.json`

已有定位稿时：只总结哪些节已填，问用户刷新哪几节，不整文件覆盖。无产品上下文则停并写缺口。用户本轮已给出公司名与站点时，可先收集公开数据点，仍不把档案写入本仓库。

## 收集

目标：在向用户补缺口之前，凑满至少 15 个可验证公开数据点。

### 公司站点

用 Apify 搜索查证公司域名；需要原文则抓取指定 URL。看：

- 首页：品类、主句、品牌主张
- 关于 / 公司：成立年、规模信号、认证、团队规模
- 产品：系列、材质或组件、定制范围
- 联系：产地、地址（以公开页为准）

逐条摘录价值主张原文、认证、出口市场、价格信号。每条记 URL。

### 目标渠道店面

用 Apify 搜索查证产品上下文里的目标渠道店面（站点检索，或公司名 + 品类 + 渠道名）。找到则摘：成交或交易记录、品类与 SKU、价格带、MOQ、主市场、买家评价原文。每条记 URL。

需要对照内外销时，再查国内目标渠道（以产品上下文为准）。不把内销价直接当出口价；记下 MOQ、包装、认证、物流差异。

### 职业主页与视频

用 Apify 搜索查证公司职业主页与视频平台公开页：

- 规模、成立年、业务标签
- 出口 / 销售角色（仅公开信息）
- 近期帖或视频里主推的产品与市场
- 评论里的买家原话

### 第三方提及

用 Apify 搜索查证：公司名 + 品类 + manufacturer / supplier / review。看名录、项目引用、报道、与对手并列出现的页面。需要原文则抓取指定 URL。

### 15 项 tally

```
[ ] 产地已核实 — 来源
[ ] 产品系列已编目（N 个品类） — 来源
[ ] 材质或组件已确认 — 来源
[ ] MOQ — 来源
[ ] 价格带 — 来源
[ ] 认证 — 来源
[ ] 出口或主市场 — 来源
[ ] 目标渠道成交记录 — 来源
[ ] 买家评价原文（N 条） — 来源
[ ] 职业主页 / 公司简介 — 来源
[ ] 销售或出口人员（公开） — 来源
[ ] 视频有无 — 来源
[ ] 第三方提及（N 个来源） — 来源
[ ] 价值主张原文（N 条） — 来源
[ ] 竞争上下文（并列出现的同行） — 来源
合计: __ / 15
```

不足 15：再做一轮定向搜索，然后才进入缺口确认。Apify 修复与替代取证后仍不可得则停止并写缺口，不编造。

### 缺口确认

一次一节，不把全部问题一次性抛出。问法只确认公开源没盖住的项：MOQ 是否仍有效、有无职业主页、标准单交期、认证编号。逼到可检查的规格，不接受 good quality 这类空话。

## 分析

只从已收集证据推导，不发明能力。

### 市场层级

按公开存在与成交证据分层，并引用具体数据点：

| 层级 | 信号 |
| --- | --- |
| 1 | 目标渠道成交 500+、认证 3+、系列完整、有面客语种团队信号 |
| 2 | 成交 100–500、认证 1–2、系列聚焦 |
| 3 | 成交 <100、出口起步、SKU 窄 |

### 价值链

按产品上下文的品类画出三层，再给中游排序：收入潜力 × 现有能力 × 评价证据。

```
上游（供应） → 中游（直接客户类型） → 下游（终端用户类型）
```

三层类型都取自证据或产品上下文，不从模型记忆填行业名单。

### 价值主张抽取

从站点与渠道原文抽出 3–5 条最强主张，逐条标记：

- **Generic**：高质量、有竞争力的价格 — 需要改写
- **Differentiating**：可验证能力（自有工序、定制匹配、指定项目负责人等），并译成买家利益

### SWOT

| | 只写有来源的 |
| --- | --- |
| 优势 | 站点、认证、评价已确认的能力 |
| 劣势 | 线上缺口、差评、缺失认证 |
| 机会 | 产品系列能支撑、但仍服务不足的市场或场景 |
| 威胁 | 搜索结果里并列的对手，或买家提到的替代 |

## 交付物骨架

不写产品档案。十五节只作分析覆盖清单（有 / 缺 / 公开源未找到），证据进入定位稿与表，不另存档案正文。

分析覆盖：业务概览、产品规格、价值链、目标市场、ICP、买家角色、问题与痛点、竞争格局、差异化、异议与不适合的客户、客户用语、品牌语气、贸易与出口、证据点、目标与指标。缺的节写「未在上下文出现」或「公开源未找到」及已试路径。

### 定位策略稿

路径：`deliverables/marketing/01-foundation/product-positioning.md`

必含：定位句、目标客群、价值主张、关键差异化、信息支柱、证据点、来源、缺口、可验证断言。下游内容 / 获客 / CRO 以本稿为依赖输入。

### 结构表

路径：`deliverables/marketing/01-foundation/positioning-data.xlsx`（表头可用 `templates/positioning-data.xlsx`）或同目录 `positioning-data.json`。三页，每行 `source` 非空。最低：每页 ≥3 行。

**Product Lines**

| 列 | 填法 |
| --- | --- |
| product_type | 品类变体（取产品上下文的品类字段，不在 skill 里填值） |
| material | 材质 / 等级 / 组件 |
| options | 表面、尺寸、定制范围 |
| price_range | 计价单位与区间 |
| moq | 起订量 |
| lead_time_days | 生产交期天数 |
| target_persona | 主买家角色 |
| source | URL 或引用 |

**Buyer Personas**

| 列 | 填法 |
| --- | --- |
| persona_name | 角色名 |
| role | 指定 / 采购 / 决策 |
| industry | 行业 |
| company_size | 营收或人数带 |
| decision_criteria | 前 3 因素 |
| pain_points | 原话或有来源的摘要 |
| value_proposition | 对该角色的承诺 |
| priority_rank | 1, 2, 3… |
| source | URL 或引用 |

**Competitive Landscape**

| 列 | 填法 |
| --- | --- |
| company_name | 真实公司名，禁止字母占位 |
| type | 直接 / 替代 / 本地制作 |
| strengths | 来自证据 |
| weaknesses | 来自证据 |
| our_advantage | 可验证的差异化主张 |
| source_url | URL |

### 可选文件

用户需要时写在同一目录：

- `messaging-matrix.md`：按角色的价值主张、差异化、异议回应
- `competitive-positioning-map.md`：二维或对比矩阵，附来源
- `brand-voice-guide.md`：语气、用词、避免的说法

异议表（写入矩阵，不编造未出现的异议）：

| 异议 | 根因 | 回应策略 |
| --- | --- | --- |
| 价格偏高 | 成本压力 | TCO、价值对照 |
| 交期偏长 | 项目节点 | 排产、加急条件 |
| 试单 MOQ 偏高 | 风险厌恶 | 样品 / 试单政策 |
| 远程如何验货 | 信任缺口 | QC、第三方检验、视频巡厂 |
| 运输破损 | 物流 | 包装、保险、既有记录 |

切换动力学（写入定位稿，有证据才写）：推离现供、拉向我方、习惯留下、切换焦虑。

## 反模式

1. 公开源已回答的还问一遍。
2. 一次抛出全部缺口问题。
3. 接受 good quality 而不逼规格、MOQ、交期。
4. 跳过价值链，导致下游客群打不准。
5. 无真实规格就写定位句。
6. 写公司无法兑现的愿望型主张。
7. 用 SaaS / 消费品牌口吻写 B2B 贸易定位，丢掉 MOQ、交期、贸易条款。
8. 结构表漏 `source`。
9. 已有定位稿时整文件覆盖，而不先问刷新范围。
10. 把十五节档案或证据库写入本仓库。

## 质量闸门

- [ ] 自动发现 ≥15 个数据点后才进入缺口确认
- [ ] 十五个分析主题均有内容或「未找到」及已试路径
- [ ] 规格里出现真实数字（MOQ、交期天数、尺寸）
- [ ] 至少 3 个买家角色，含 role、行业、决策标准
- [ ] 竞争格局是真实公司名
- [ ] 客户用语是有来源的短语，不是套话
- [ ] 结构表每页 ≥3 行
- [ ] 每行 `source` 非空
- [ ] 定位稿已过证据闸（`docs/feedback-rules.md` 第 9 节），或标明卡在哪条

## 可验证断言

交付物末尾写 5–10 条评审可勾的断言，至少覆盖：

1. 收集数据点 ≥15，每条有来源。
2. Product Lines ≥3 行真实产品线。
3. Buyer Personas ≥3 行，每行有 role、industry、decision_criteria、value_proposition。
4. Competitive Landscape ≥3 行真实对手，无占位名。
5. 结构表 `source` 覆盖率 100%。
6. 十五个分析主题均有内容或「未找到」。
7. `product-positioning.md` 含定位句、信息支柱、关键差异化。
8. 抽出的价值主张均标 Generic 或 Differentiating；Differentiating 有证据。
9. 规格中 MOQ、交期、尺寸或认证至少两项有数。
10. 客户用语至少 3 条买家原话并带来源。

## 例子

> 仅供理解，禁止引用到输出。

公开成交显示某起订量。先记来源，再问「该起订量是否仍有效」，不问「你们 MOQ 是多少」。中游排序用「收入潜力 × 现有能力 × 评价证据」，不凭职位直觉把某类客户放第一。内销页价格不抄进出口定位句。
