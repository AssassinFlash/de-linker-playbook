# 首单引导（买家信心 + 转换摩擦）

为首单海外买家写可发送的双语引导：清单、欢迎信、共享文件夹规范、软锁定装置、转换摩擦提示，落到 `deliverables/lead/10-sales/first-order.md`。缺证据标缺口，不编造交期、投诉或未建设的系统。

## 步骤

1. **共用规则**。读 `skills/marketing-playbook-standards/SKILL.md`。完成：能复述数据锚定、例子禁引用、产出根、工具写能力。

2. **输入**。读台账 `state/status.md` 的 `product_context`（默认 `~/Documents/New/CONTEXT.md`；把 `~` 展开为主目录，不当相对路径）。硬依赖：已批准的 `deliverables/lead/10-sales/objection-handling.md`，或台账 `user_waiver`。未满足则停，宣布打开 `skills/lead-service-objection/SKILL.md`（文件存在时），不自造异议史、不跳到交付沟通。软依赖（有则读，不阻塞）：`deliverables/lead/10-sales/quotation-strategy.md`、`deliverables/lead/10-sales/first-contact.md`、`deliverables/lead/01-icp/icp-analysis.md`。闸门口径见 `skills/lead-generation/references/dependency-graph.md`，本文件不另写审批。从这些来源填四格：所交产品（名、规格、包装）、买家类型、确认订单到出货的交期、已知 onboarding 投诉。产品、买家类型或交期仍缺到无法下笔：先看用户本轮；仍缺则打开 `skills/lead-interview/SKILL.md`（存在则按其做），否则停并写缺口。完成：四格各有依据或已标「未在上下文出现」；原文不拷进本仓库。

3. **查证**。用网页搜索查证两类材料：B2B 出口首单 onboarding 实务（确认后到收货的节点、文件、联络节奏）；该品类或外贸首单的常见投诉（沉默、文件缺口、包装预期、质检节点）。品类取产品上下文，不在 skill 里填值。需要原文则抓取指定 URL。搜索不可用：不编造买家原话、研究名或投诉率；投诉只保留上下文与异议稿里已有的；搜索日志记「不可用」。搜到的是泛外贸而非本品类 → 采用并标明「已泛化」。完成：日志至少两类查询，或已记不可用；写入清单的痛点能回溯 URL / 异议稿 / 上下文。

4. **设计五件套**。按「写法」写：买家可见清单、欢迎信、共享文件夹规范、软锁定装置、转换摩擦提示，外加实施时间线（Day 1 / Week 1 / 生产期 / 出货前）。清单覆盖确认→生产→质检→出货→收货的预期，不代替 `lead-service-delivery` 的过程更新。买家类型不同则节奏、文件深度、进口准备项不同。每条已知投诉在清单或欢迎信里有对应一行。软锁定只写本流程能落地的便利。完成：五件套 + 时间线齐全；每件锁定装置写清买家收益与实施时点；摩擦提示只预告可兑现的未来便利；教学支架原文零出现。

5. **落盘** `deliverables/lead/10-sales/first-order.md`。面客段（清单、欢迎信、摩擦提示）填入上下文里的买家名、产品、数量、交期、联络人；缺的用「未在上下文出现」，禁止残留 `{{...}}`。验证—审查—审批走 `skills/lead-generation/references/orchestration-protocol.md`，本 skill 不代替审批。完成：文件非空；断言满足。

## 写法

首单是试镜，不是一笔货：沟通速度、是否主动、文件是否齐、包装是否按约定，都在决定有没有第二单。多数首单投诉来自沉默而非事故——节点未到也要按约定节奏更新，细节交给交付 skill。共享工件（订单履历、对方内部编号、联络树）会变成对方的操作基建，转换供应商等于重做一套，这是便利带来的摩擦，不是合同惩罚。引导深度跟买家成熟度走：电商转售要包装、平台合规、入仓节点；批发要批次与再订；品牌方要规格锁定与检测格式；分销要区域与主数据。

**买家可见清单**。编号 + 复选框，邮件或共享文档可直接转发，不需二次编辑。每一阶段写四格：买家会看到什么、买家要准备什么（进口文件、清关、收货物流——只写该买家类型用得上的）、里程碑日期或「订单确认后 T+N」（N 只来自交期格，没有则 `[待补充]`）、该类问题找谁（姓名缺失则角色 + 「未在上下文出现」）。已知投诉写成清单上的预防行，不另开空话段落。

**欢迎信**。确认后立即发。口吻热而不套；确认产品、数量、时间线；写清沟通节奏（谁、哪个渠道、多久一次）；点名唯一对接人；带一条可兑现的额外价值（生产预览、包装样张、检测节点说明——上下文没有可兑现项则删这一句，不编造预览）。禁止公司简介式开场。

**共享文件夹规范**。至少下列五类，每类写：里面有什么、何时更新、买家为什么需要。

| 工件 | 最低内容 |
| --- | --- |
| 订单追踪 | 状态、关键日期、里程碑 |
| 联络树 | 生产 / 质检 / 出货 / 售后各找谁 |
| 包装照片 | 出货前包装记录 |
| 质检报告 | 主动分享的检验结果 |
| 规格页 | 与本单一致的规格 |

一次不把全部历史文件砸给买家：Day 1 放追踪 + 规格 + 联络树；生产期加进度；出货前加包装与质检。

**软锁定装置**。用便利做切换成本，每条必须同时有买家收益和实施时点：

- 对方内部编号：按买家库存体系给专用编码，减少对方二次录入
- 时间线看板：跨订单累积的共享进度，第二单不用从零解释
- 再订表：预填本单规格、偏好、历史数量
- 定制文件：COA / 检测 / 合规按买家模板出；模板未知则 Day 1 问，不编造对方格式

禁止写成最低采购量合同、独家条款或「不续约即失效」的惩罚。未建设的一键下单系统不许写进装置。

**转换摩擦提示**。出货前或质检通过时发，不塞进欢迎信。只预告下一单可沿用的便利（编号、再订表、共享履历），要真实可做。让买家期待再订，不让买家觉得被锁。

**实施时间线**。Day 1：欢迎信、共享文件夹开通、清单发出、要对方内部编号规则。Week 1：追踪表第一次更新、问检测模板。生产期：按节奏更新，不代替周报模板。出货前：包装照片、质检、再订表初稿、摩擦提示。

## 例子

> 仅供理解，禁止引用到输出。

输入写「买家刚填完注册，发欢迎信并开放下单」。成稿应拆审批前/审批后：审批前只收齐公司主数据（行业分桶、税号、交货点卸货能力、会计联络），未激活就不发可下单清单；审批后才确认行项目、唯一对接人、沟通节奏。不要编审批时限，不要照抄贸易店注册页原句。

输入写「把认证和并网文件一次打包」。共享文件夹应改成买家文件栈分层：Day 1 放本单规格、订单追踪、联络树；出货前再附与本单型号/序列号对齐的在案文件类型。不要一次砸出并网申请全套，不要写代为并网登记或完整外语文档包，不要把质保年数、备件库存年限写成我方承诺。

输入写「安装商首单，感谢成为合作伙伴」。成稿应写成备线开通：确认数量与本单交期口径（按目的地，不写通用交期表），对接人覆盖出货后，不要交货即失联或公司简介开场。摩擦提示预告第二单沿用规格、对方内部编号与共享履历，不要写「不续约失去优惠」或未建设的一键下单。电商转售清单要有包装与入仓；批发侧重批次与再订；EPC/品牌方要有文件包评分项与质保登记责任人——不能互贴。欢迎信只清已有订货卡点（货款状态、随货文件、谁对接），不要种升档、误订、理赔年数。首单支付写成形式发票/预付，不要把账期当默认；不要自称制造商、备件库或自有质保承保。本节句子不得进入交付物。

## 易错

- 没读异议稿、没填四格就套通用引导。
- 把清单写成交付周报，或把本文件当 `lead-service-delivery`。
- 欢迎信像公司模板，或把摩擦提示塞进第一封。
- 一次丢出全部文件，买家不知先看什么。
- 锁定装置写成合同义务或惩罚。
- 承诺一键再订、实时看板等上下文没有的系统。
- 忽略已知投诉，重复已经出过的错。
- 不写沟通节奏或唯一对接人。
- 只有英文或只有中文。
- 编造交期天数、员工名、投诉率或买家原话。
- 所有买家类型共用一份清单。
- 把 skill 例子原文写入交付物。
