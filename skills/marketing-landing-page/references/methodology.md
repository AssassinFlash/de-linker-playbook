## 输入

先读事实源入口 `docs/fact-sources.md`（台账 `product_context` 即指向它），按其「什么问题查哪个源」取证；查不到标〔未证实〕，按没有处理。上游若已存在则读：

- `deliverables/marketing/01-foundation/` 定位、买家角色、定价与样品政策
- `deliverables/marketing/02-seo/seo-audit.md` 页面与技术约束
- 已有 CRO / 漏斗分析（`deliverables/marketing/05-cro/`）

再列出（未知则记缺口，不编造）：

- 漏斗：访问 → 询盘 → 样品 → 订单 → 复购，及用户已给的转化率
- 流量来源与询盘渠道：只记产品上下文已出现项（付费搜索、自然搜索、目标渠道、职业社交、展会转介、表单、即时通讯、邮件）
- 买家角色、建站平台与主题/表单插件限制

产品事实不写进 skill，不另写公司档案。品类、目标市场、产地只引用产品上下文对应字段，不在本文填值。

缺项列缺口后停。用户只给站点 URL、上下文仍缺品类或市场：抓该站能核实的事实后停，不进入落盘装成已完成。

## 采集

默认一条能力：用网页搜索查证。需要原文时抓取指定 URL 的正文。搜索不可用则停止并写缺口，不编造、不并列多引擎菜单。

### 本站页面

抓取并摘录（不可访问则记下状态与原因，换下一 URL，不编造结构）：

1. 首页 — 价值主张、标题、CTA 层级、信任信号
2. 产品 / 品类 / 服务页 — 规格完整度、CTA 位置、视觉层级
3. 询盘 / 联系 / 报价页 — 字段、必填、信任元素、摩擦
4. 下单流程或 How to Order 页（有则抓，无则记缺口）— 样品政策、交期沟通

字段数与 CTA 原文必须来自已抓取正文。

### 竞品对照（≥3）

每个竞品抓首页 + 产品/服务页 + 询盘页；有公开的下单流程页则一并抓（伙伴/转介绍计划页不是本 skill 采集目标）。记录：CTA 位置与原文、信任信号、表单字段数与必填、价值主张清晰度、社会证明、弹窗/横幅是否出现。页面不可访问则记下原因并换下一个。

### 查询意图

把产品上下文的品类与目标市场代入下列意图，每条记下 URL、摘录、访问日期：

1. 该品类 B2B 着陆页转化做法
2. 报价 / RFQ 表单优化
3. B2B 询盘页字段与 CTA 做法
4. B2B 弹窗获客（目录、样品）做法
5. 着陆页上的展会/上市横幅与页面级预告（不采集整份上市计划）
6. 询盘表上来源字段或页上转介绍入口（页面级，不采集佣金或留存手册）

结果不够时再补：制造转化案例、页上询盘入口综述。仍用同一条搜索能力。

### 最低数据量

进入分析前至少备齐；达不到的写入缺口，不降低后项装成已完成。

- 本站：首页 + 1 个产品/服务页 + 1 个询盘页，均已抓取
- ≥3 个竞品页：CTA、信任信号、表单结构
- ≥2 个竞品询盘表：字段数、必填、CTA 原文
- ≥2 个竞品下单/流程页（无则整项记缺口）
- B2B 制造着陆页/询盘率/字段数公开基准，标「行业参考值，实际以你的数据为准」

多页抓取需要隔离时 dispatch a subagent, else do it inline。

### 校验

- 每条已分析页须核实可访问；不可访问不写结构
- 竞品 CTA / 表单只来自已抓取正文
- 禁止编造转化统计
- 每条建议引用 URL 或本轮已采集来源

## 分析

### 漏斗

把发现映射到外贸漏斗，不套用注册或订阅模型：

```
访问 / 广告 / 名录 / 展会
        ↓
产品浏览 / 着陆页
        ↓
首次联系（表单 / 即时通讯 / 邮件 / RFQ）
        ↓
首次回复 → 资质与报价
        ↓
样品 / 试单
        ↓
大货确认
        ↓
复购 / 转介绍
```

整条询盘到报价的摩擦、回复框架与样品桥接：打开 `skills/marketing-inquiry-flow/SKILL.md`。跨阶段合成打开 `skills/marketing-funnel-optimization/SKILL.md`。本 skill 只写着陆页上的入口、字段与 CTA。

### 页面审计维度

每页 1–5 分：

| 维度 | 评什么 |
| --- | --- |
| 价值主张清晰度 | 五秒内：卖什么、为何在此、服务谁 |
| 标题效力 | 买家利益语言，不是空泛宣称 |
| CTA 位置与层级 | 高/中/低意向按钮沿页重复 |
| 视觉层级与可扫读 | 图、规格表、留白 |
| 信任信号 | 认证、产能可信度、案例、服务过的客户类型 |
| 异议处理 | MOQ、交期、质量核验、运输风险 |
| 移动体验 | 点击热区、粘性 CTA、即时通讯是否可见 |
| 平台约束 | 主题、表单插件、名录页限制（以产品上下文为准） |

B2B CTA 层级：

- 高意向：Request Quote / Send Inquiry / Get Custom Quote
- 中意向：Download Catalog / Request Sample
- 低意向：View Portfolio / See Project Cases

面客原文跟产品上下文语种，上表是意向标签不是必须英文。

### 表单

| 原则 | 标准 |
| --- | --- |
| 字段成本 | 每多一字段降完成率；RFQ 桌面 5–7，移动 3–4 |
| 适当摩擦 | 够资质、不至于放弃 |
| 渠道选择 | 目标市场已出现的即时通讯与表单并列 |
| 布局 | 单列、移动优先；7+ 字段才拆步 |
| 按钮文案 | 行动 + 结果，不用 Submit |
| 表旁信任 | 回复时效承诺、认证、贸易条款 |

常见表类型（按页上实际出现的来改，不发明用户没有的表）：RFQ / 询盘、样品申请、目录下载、快速报价。

询盘表可保留的字段方向：姓名、邮箱、即时通讯、国家、项目类型、规格、数量、交期。样品表另加表面/变体与收货地址。目录下载可压到邮箱 + 姓名。以已抓取页为准做删/留/改，不整表照抄。

### 弹窗与获客层

B2B 弹窗给研究加资产，不打断规格阅读。

| 漏斗阶段 | 类型 | 触发 | 提供 |
| --- | --- | --- | --- |
| 访问 → 询盘 | 退出意向目录下载 | 光标离开 | 目录 PDF |
| 询盘 → 样品 | 滚动触发样品 | 约 60% 滚动 | 样品说明 |
| 任意 | 即时通讯浮层 | 常驻 | 直聊（频道以上下文为准） |
| 上市 / 展会 | 横幅 | 有时限 | 展位预约或上市预告 |

每个弹窗写：类型、触发、定向、频率上限、标题、副标题、CTA、拒绝文案；目标市场含欧盟流量则加同意勾选。无欧盟迹象则该项记「未适用」，不编造合规条款。

### 询盘路径（薄）

只评着陆页入口：字段摩擦、首屏是否有表单或即时通讯、回复时效若页面已承诺则摘录。首次回复话术、七维资质评分、样品桥接节奏不在本文件展开，见 `skills/marketing-inquiry-flow/SKILL.md`。

方法默认（行业参考值，实际以你的数据为准）：工作时间内 2 小时首次回复。

### 上市 / 转介绍 / 留存

用户点名这些主题时打开对应方法 skill，不要在 `cro-experiment-queue.xlsx` 加那些表。

- 上市：Owned / Rented / Borrowed 把人带回自有关系；Pre-Launch / Launch Week / Post-Launch。见 `skills/marketing-launch-strategy/SKILL.md`。
- 转介绍类型（指定人、承包、经销、老客户）与追踪（询盘「从何得知」、推荐日志、来源标记）若用户只要一句话衔接，可在主文档缺口或下一步指出，不写佣金数字除非产品上下文有毛利。
- 留存信号用订单频率、报价未转化、价格反复异议、90 天无联系、反复要规格文件；不用日活。健康分若用户要公式：订单频率 0.35 + 订单额 0.30 + 沟通 0.20 + 关系 0.15，权重须标明假设。完整手册走留存方法 skill。

## 交付

主文档 `deliverables/marketing/05-cro/landing-page.md`，每条建议引用已采集来源：

1. 现状审计 — 页面得分、表单审计、已知漏斗数字（未知则缺口）
2. 竞品 Benchmark — ≥3 家，CTA、信任、表单、流程
3. 着陆页优化方案 — P0/P1/P2，before → after 与来源
4. 表单与询盘入口方案 — 逐字段删/留/改、渠道、页面已承诺的回复
5. 弹窗与 Lead Capture 方案 — 规格、触发、频率上限
6. KPI 追踪计划 — 指标、目标、量法、来源
7. 行动清单 — P0 必做 / P1 建议 / P2 可选
8. 缺口
9. 可验证断言

工作簿从 `templates/cro-experiment-queue.xlsx` 复制后填：

| 表 | 列 | 最低行 |
| --- | --- | --- |
| Experiments | experiment_id, page, hypothesis, metric, variant, priority, effort, impact, status, source | ≥10 |
| Results | experiment_id, start_date, end_date, visitors, conversions, lift_pct, significance, source | 0（测后填） |
| Page Audit | page_url, page_type, value_prop_score, headline_score, cta_score, trust_score, mobile_score, issues, priority_fix, source | ≥5 |
| Form Redesign | form_url, field_name, current_state, proposed_state, required, rationale, priority, source | ≥8 |
| Popup Plan | popup_name, trigger, page_target, offer, headline, cta, frequency_cap, priority, source | ≥6 |

不能写表时改同目录 `cro-experiment-queue.json`，字段同名。禁止只交空模板。

按需附件（同目录）：`page-audit-findings.md`、`copy-rewrites.md`、`form-field-spec.md`、`popup-designs.md`、`ab-test-plan.md`。

不产出：定位文档、SEO 关键词策略、付费投放计划、独立站技术重构、询盘回复模板全集、上市时间线、转介绍设计、留存手册。

## 反模式

- 把 SaaS 注册/试用战术套到询盘与报价
- 不抓本站就给改版建议
- 忽略建站平台与主题限制
- 编造转化基准，或行业数字不标「行业参考值，实际以你的数据为准」
- 跳过竞品对照
- 建议无来源
- 把教学例子原文写入交付物
- 对 B2B 采购用网红带货或病毒噱头
- 转介绍或加售比例未对毛利
- 挽回只发一次就停（B2B 至少 3–4 次触达，且应走留存方法 skill）

## 质量闸门

- 本站首页 + 产品/服务页 + 询盘页已抓取
- ≥3 竞品页有来源 URL
- 询盘表有完整字段与必填/选填
- ≥2 竞品表单有字段数与 CTA 原文
- 制造基准已采集并标参考值
- 每条建议有来源
- 语境保持询盘/报价，不是注册
- 即时通讯是否启用以目标市场为准
- 每个 P0 有 before → after
- 工作簿每表有 `source`
- 无占位域名，只用已核实域名

## 可验证断言

交付物文末写 5–10 条，须能对照文件检查。默认检查这些（做不到的改写成缺口，不假装完成）：

1. 首页、≥1 产品/服务页、≥1 询盘页已抓取且可访问。
2. ≥3 个竞品页已分析，Benchmark 每项有来源 URL。
3. `landing-page.md` 每个 P0 含 before → after，并引用采集来源。
4. Experiments ≥10 行且每行有 `source`。
5. Form Redesign ≥8 行，含当前、建议、必填、理由。
6. Popup Plan ≥6 行，含触发、目标页、频率上限；欧盟流量适用时有同意勾选说明。
7. 转化率、字段数、响应时长等行业数字均标「行业参考值，实际以你的数据为准」。
8. 询盘入口方案覆盖产品上下文已出现渠道中的至少 3 个，或已写渠道缺口。
9. 工作簿无上市时间线、转介绍、留存表。
10. 教学例子原文未进入交付物。
