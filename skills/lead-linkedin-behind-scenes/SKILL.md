# LinkedIn 幕后流程帖（Structure 3）

把一条真实的内部工序写成可发布的 LinkedIn 幕后帖：用画面证明过程，把内部严谨译成买家价值。落到 `deliverables/lead/08-linkedin/`。本 skill 只产帖稿；用户自行发布，或经用户已配置的工具发布。工序、质检步骤、缺陷率缺证据则标缺口，不编造。

## 步骤

1. **共用规则**。读 `skills/marketing-playbook-standards/SKILL.md`。篇幅、钩子、CTA、标签、四种风格、软广：读 `skills/lead-generation/references/linkedin-post-guidelines.md`（只遵守，不把该文抄进本文件或交付物）。完成：能复述数据锚定、例子禁引用、产出根、工具写能力，以及本帖必须走 Structure 3。

2. **输入**。读台账 `state/lead-status.md` 的 `product_context`（默认 `~/Documents/New/CONTEXT.md`；把 `~` 展开为主目录，不当相对路径）。需要参数再读 `~/Documents/New/fact-base/`。无硬依赖。软依赖存在则读：`deliverables/lead/05-usp/usp-strategy.md`、产品知识稿（`deliverables/lead/05-usp/product-knowledge.md` 或 `deliverables/lead/10-sales/product-knowledge.md`，以磁盘已有为准）。ICP 存在则读 `deliverables/lead/01-icp/icp-analysis.md`（定受众与买家关切）；缺失不阻塞，受众改从产品上下文或本轮取，并注明「ICP 未在上游出现」。用户本轮给出的工序、画面、CTA 一并吸收，来源记「用户本轮」。原文不拷进本仓库。从已读材料填齐下方七项，已有的不问：
   1. 目标海外受众 / 市场
   2. 本工序对应的产品或品类
   3. 要展示的那一步内部工序（进料检、某一机加工序、装配、包装、出货检验等，必须具体到一步）
   4. 该步事实上发生了什么（动作、检查、设备），只写材料里有的
   5. 相对通行做法有何不同（选填；没有就不写优越）
   6. 可用视觉：已有照片 / 短视频的画面描述，或尚未拍摄
   7. 希望读者采取的一个动作
   核心两项：产品或品类，以及第 3–4 项工序事实。缺核心：先看本轮消息；仍缺则打开 `skills/lead-interview/SKILL.md`（存在则按其做），否则停并只要这两项。不要在本文件另写七问问卷。第 6 项缺失仍可起草，但 `visual_status: missing`，不算可发布。完成：能指出七项各依据哪几条；保密或「勿外传」的工序只写到用户已公开的粒度，不补隐藏步骤。

3. **查证（按需）**。工序本身禁止用搜索补造。仅当要把内部动作译成买家价值、或要对齐公开的幕后帖角度时，用网页搜索查证该品类该工序对买家品质 / 交期 / 合规的意义；需要原文则抓取指定 URL。搜到的帖只作角度，禁止把原文写入交付物。搜索不可用或本轮用不到数字与竞品角度 → 搜索日志写「本轮未检索」，只用已有工序事实写帖，不编造行业缺陷率或「普遍抽检比例」。禁止为凑次数空搜。多工序需隔离时 dispatch a subagent, else do it inline。完成：凡含数字的句子能指回来源；无数字则日志已写未检索。

4. **起草**。按「写法」写一篇完整可复制的英文帖，严格 Structure 3 六拍：Hook → Process → Differentiation → Visual → Benefits → CTA。无第 5 项则 Differentiation 拍只陈述该步在流程中的位置，不写「优于同行」。视觉拍必须有一句指向配图或视频的指示；无现成画面则改写拍摄要点，并在帖中用「this step」一类指向，不假装照片已附。用户点名微博客 / 故事叙事 / 滑梯式 / 直销节奏时，按 guidelines 只改语气与结构，不改工序事实。面客语种以产品上下文为准（缺省英语）；策略笔记用中文；同一段不中英混排。完成：六拍齐全；钩子对准该步工序；利益从该受众读得懂；恰好一个 CTA；文后 3–5 个标签。

5. **质检并落盘**。按清单与 guidelines 出门清单自检后写入 `deliverables/lead/08-linkedin/behind-scenes-post.md`。仅当用户本轮要求发布 **且** 已配置发布工具时才发；否则 `publish_status: copy_only`。付费发布须先告知并获准。完成：主文件非空；含输入映射、英文帖、视觉说明、中文策略、来源、搜索日志、缺口；教学例子原文零出现。验证—审查—审批走 `skills/lead-generation/references/orchestration-protocol.md`，本 skill 不代替审批、不代替发布。

## 默认

- 产品事实只读台账 `product_context`（需要参数再读 `~/Documents/New/fact-base/`），不在本仓库另存档案。
- 无硬依赖，可独立执行。软依赖：USP、产品知识。产地、工厂所在地、目标市场以产品上下文为准，不预设某一出口国。
- 本帖类型写 **内部发生了什么**（设备、工序、质检、原料到在制品）。出口法规、物流、认证知识走 `skills/lead-linkedin-expertise/SKILL.md`（文件存在时）。创始人或团队的人的故事走 `skills/lead-linkedin-personal-story/SKILL.md`（文件存在时）。选题卡走 `skills/lead-linkedin-topic-research/SKILL.md`（文件存在时）。多平台日历或战役走 `skills/marketing-social-content/SKILL.md`（文件存在时）。本文件不写那些帖型。
- 查证用网页搜索；需要原文时抓取指定 URL。不并列搜索引擎菜单。搜索不可用则停止数字与竞品角度并写缺口，不编造。
- 发布：用户自行发布，或经用户已配置的工具发布。未配置或未要求发布 → 只产帖稿。
- 进度只认台账。产出只进 `deliverables/lead/08-linkedin/`。Markdown only，无 Excel。
- 单帖 inline 做完。需要隔离时 dispatch a subagent, else do it inline。
- 数字、证书、案例、缺陷率、抽检比例、设备型号：产品上下文、用户本轮或已抓取页里有才写。没有就写「未在上下文出现」或删掉该句。

## 写法

- **Structure 3（固定六拍，顺序不改）**
  1. Hook：对准这一步工序开场；种类与禁开场见 guidelines
  2. Process：短、可核验，写这一步实际做了什么
  3. Differentiation：有证据才写特殊或更严之处；没有则不写优越
  4. Visual：明确指向配图或短视频（特写、设备运转、技师操作、检测台、专用设备）
  5. Benefits：把内部严谨译成该海外买家拿到的结果（少什么风险、多什么可验的确定性），不堆设备名
  6. CTA：用户指定的那一个；未指定则按 guidelines 选恰好一个接得上正文的
- 用画面证明，不用空话品质。没有可描述的画面，就写拍摄要点，不改口声称「品质很好」。
- 内部动作必须落到买家：交期、一致性、到货状态、可追溯、验货省事。禁止用无来源的行业缺陷率当对照。
- 买家可远程看到这一步，当作不能到厂时的透明窗口；不把「到不了厂」写成某一产地的刻板印象。
- 短段、段间空一行、专业而像内部走一圈，不像宣传册。非专家买家读得懂；必要术语跟一句人话。
- 软广：产品最多 1–2 句且可删；删掉后帖子仍应能讲清这一步。规格堆砌删掉。
- 标签 3–5 个，放 CTA 之后；组合见 guidelines。品类标签取产品上下文，不在本文件填值。

## 例子

> 仅供理解，禁止引用到输出。

输入写「我们做质检」。草稿应改成流程链里的**一步**（第几层纸件、核什么、对照哪条门槛、产出哪一份可归档的东西），把该动作译成买家少承担什么风险，并点名已描述的照片或短视频。形状借询价七层纸件（谁写 / 决定什么）和 EPC 采购双闸：商务闸看价与有效窗口，技术闸看证件与配对证据，后者可否决前者。一帖只过一闸、只交一层的一行 deliverable；主语是核验动作，不是产线或规格巡游。行业店把「能报价」当成规格、价表、合同那几层已齐，只回一个价等于只答了价表层——幕后帖同理，不要用出货照冒充整叠纸件。

不要把整叠写成工厂巡游。没有产线或缺陷率就不要发明进料检、机加、「零缺陷」或「行业抽检百分之几」；没有库存与时效承诺就不要写现货或全天响应。目录批发「卖箱子、交货后沉默」那种出货花絮不要当本帖形状。不要把本节句子粘进交付物。

## 易错

- 没读产品上下文就发明产线、设备或质检标准。
- 把教学例子或搜到的幕后帖原文写入交付物。
- 无画面仍当可发布，或在正文假装「见下方照片」。
- 空泛「我们很重视品质」，没有具体一步。
- 写出上下文标明保密的工艺细节。
- 术语堆到非专家买家读不下去，或写成工厂宣传册。
- 用无来源的缺陷率、抽检比例、互动率承诺当卖点。
- 写成出口合规知识帖或创始人故事帖。
- 未配置发布工具仍发布，或把成稿当成已发出。
- 终稿残留未解释的 `{{...}}`，或把 `[待补充]` 假装成已核实数字。
