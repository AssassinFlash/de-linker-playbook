# 公开页查证

条件：步骤 4 需要查询形状、抓取目标或置信度时读本文。执行顺序与完成条件以 `SKILL.md` 为准。

## 默认与逃逸

每个域名只走一条默认能力、一个逃逸，不并列引擎菜单。

| 需要 | 做法 |
| --- | --- |
| 查证人名、职位、公开邮箱、职业页 | 用网页搜索查证 |
| 需要页面原文（联系页、About、Team，含动态页） | 抓取指定 URL 的正文 |
| 搜索不可用 | 停止并写缺口，不编造 |
| 抓取失败（反爬、登录、验证码） | 换一条查询或停止对该域；记入搜索日志。不把训练记忆填进字段 |
| 补邮箱 | 回到 `SKILL.md` 步骤 5：仅当用户已配置联系人/邮箱发现服务 |

同一能力下可以换查询，不因此换成另一套工具名单。

## 查询顺序

花括号是字段，不要把花括号抄进交付物。职位取本轮范围（缺省见 `SKILL.md` 步骤 3）。

1. `"{company_name}" {job_title} email`
2. `"{company_name}" procurement contact` 或本轮等价职位
3. `"{company_name}" sourcing team`
4. `site:{domain} contact`
5. `site:{domain} team`

前几条无可用结果时，再搜 `"{company_name}" {job_title}` 找公开职业页。不要为同一域名无限追加近义词。

## 抓取目标

对搜索里出现的官方域，优先抓取：

- `{domain}/contact` 或 `{domain}/contact-us`
- `{domain}/about` 或 `{domain}/about-us`
- `{domain}/team` 或 `{domain}/our-team`

页面正文与 `mailto:` 链接都算来源。动态目录、点开才显示的团队页：仍用「抓取指定 URL 的正文（含动态页）」；失败则记缺口，不改走未配置的采集服务。

目录站、交易平台列表页、内容农场不作为联系人来源。

## 通过 / 不通过

**通过（可写入真实联系人行）：** 已抓取页上出现至少一项：商务邮箱、公开电话、公开职业页 URL；有人名则一并写入。

**不通过：** 只有公司名；只有表单无地址；只有消费邮箱；登录墙后才能看。该公司仍落一行「联系人待补」。

## 入库规则

- 只采公开商务联系方式。
- 消费邮箱域名不入库（该行改标「联系人待补」）。
- 通用收件箱（`info@`、`sales@`、`purchase@`）可入库，`job_title` 为 `generic_inbox`，`contact_name` 不编。
- `linkedin_url` 列只填已抓取到的公开职业页 URL，不要求登录后抓取。
- 无用户授权不抓登录墙后内容。

## 置信度

| 情形 | confidence |
| --- | --- |
| 两个以上独立来源交叉验证 | `high` |
| 单一来源，邮箱与公开职业页都有 | `high` |
| 单一来源，只有邮箱或只有职业页 | `medium` |
| 只有人名与职位，无直接联系方式 | `low`（邮箱仍标「联系人待补」） |
| 公开页与发现服务都无结果 | 留空，整行「联系人待补」，不要省略该公司 |

来源写入 `data_source`（查询或 URL）与 `collected_date`（YYYY-MM-DD）。

## 批次

- 单家公司：本会话做完。
- 多家且需隔离：按 ICP 或域名批 dispatch a subagent, else do it inline。子代理只回传已标注行 + 搜索日志；分类合并在本会话完成。
- 同一域名短时间反复失败：停止该域，不循环。
