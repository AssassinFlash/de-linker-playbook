# Listicle 大纲模板

条件：类型锁定为 Listicle 时读本文。执行顺序与完成条件以 `SKILL.md` 为准。

> 仅供理解，禁止引用到输出。

本文全部例子都是教学支架，禁止把原文写入任何交付物。标题公式是产出形状，交付物须换成目标关键词与受众，不得整段照抄。

## 何时用

可扫读的清单：工具、要点、错误、趋势条目。关键词过宽则收到一个清单类别（Top tips / tools / mistakes），不写成 Ultimate Guide。

## 必含块

### 1. Title (H1)

- 含目标关键词，以数字领句（Top 10、7、15）。
- 标题数字必须等于正文 H2 条目数；写 10 就列 10。
- 时效性主题才加运行当日公历年。
- 可加角度（价值、反直觉、限定受众），角度须能被条目证明。
- 公式：`[数字] [对象] [限定 / 结果]`。

### 2. Meta Description

- 目标 150–160 字符，写出字符数。
- 含关键词，提示清单能解决什么。
- 不用「in this blog post, we will explore…」。不为点击编造「#3 is a game changer」这类无来源排序。

### 3. Introduction（要点，最多约 150 词）

- 开场：可核验事实、常见卡点、或此刻需要这份清单的原因。
- 预告清单对象（工具 / 要点 / 错误），不剧透编造的「第一名」。
- 语气跟上游 `editorial-guidelines.md`。

### 4. 条目（每条一个 H2）

各条深度大致相当。成稿每条目标 150–300 词，大纲用 3–5 条子弹撑住该长度。

H2 公式按清单对象选一档并全篇锁定：

- 工具：`名称 — 解决什么`
- 要点：`动作 — 好处`
- 实例：`对象 — 为什么重要`

每条子弹覆盖：是什么或做什么、解决什么、适用场景、优劣或边界、可链到的真实 URL（有才写）。禁止每条套同一套好处句。

### 5. Bonus（推荐，可省略）

Honorable mentions、过时项、或未进主清单但值得一句的选项。用来显示取舍，不把主清单数字改掉。无真实增量则省略。

### 6. Conclusion（要点，约 100–150 词）

- 收回清单对读者的用处。
- 可点名 1–2 条最贴本轮受众的项，须能指回上文条目。
- 下一步：相关篇、要规格 / 要报价 / 要样品。不逐条复读整个清单。

### 7. Semantic keywords

- 目标 30–50 个，一行一词，来自本轮搜索。
- 三组：主题变体、意图限定（for beginners、budget、当年若确为时效）、问句。
- 优先能接到某条 H2 的长尾。不够则少写并标缺口，不垫词。

## 排版给下游

- 编号列表、可扫读、移动端短段。
- 默认不用 emoji；产品上下文要求时才标。
- 建议配图处写「logo / 截图 / 示意」，不编未持有的品牌图。

## 约束

- 条目必须可区分；两条不能只换同义词。
- 内链或推广链接只建议真实存在的页；用户未要求联盟链接则不写联盟。
- 语气跟受众：专家直说，入门少缩写。不把同一稿用于所有角色。
