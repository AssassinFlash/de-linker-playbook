# How-to 大纲模板

条件：类型锁定为 How-to 时读本文。执行顺序与完成条件以 `SKILL.md` 为准。

> 仅供理解，禁止引用到输出。

本文全部例子都是教学支架，禁止把原文写入任何交付物。标题公式是产出形状，交付物须换成目标关键词与受众，不得整段照抄。

## 何时用

单一可完成任务或流程：读者做完有明确结果。主题过宽则收到一个任务，不写成支柱页。

## 必含块

### 1. Title (H1)

- 以 How to 起句，自然含目标关键词。
- 写清任务或结果，不写空的 Get Started。
- 时效性主题才加运行当日公历年。
- 公式：`How to [任务] [限定：受众 / 工具 / 结果]`。

### 2. Meta Description

- 目标 150–160 字符，写出字符数。
- 含关键词，写清做完得到什么。
- 不为点击编造时限或成功率。

### 3. Introduction（要点，100–150 词量级）

- 开场：痛点、可核验事实、或读者要完成的结果。
- 写清为什么现在做、做完得到什么。
- 立即有用，不铺垫悬念。
- 人称与语气跟上游 `editorial-guidelines.md`，不在本模板另定。

### 4. What You'll Need（推荐；没有则整节省略）

- 列出完成任务所需工具、材料、权限或前置知识。
- 写具体物，不写空的「相关工具」。
- 只列产品上下文或本轮查证里真实存在的项。

### 5. Step-by-step（每步一个 H2）

- H2 写成 `Step N: [动作 + 结果]`。
- 总步数 5–8；微步骤合并，不靠拆步凑数。确需超过 8 步时在缺口写理由。
- 每步 3–5 条子弹：动作、易错、涉及的设置或材料、本步完成标准、建议配图（截图 / 清单 / 示意图）。
- 每步有可检查的小结果，不只描述「点哪里」。

### 6. Bonus tips（可选）

- 只写能改变结果的进阶做法。
- 无真实增量则整节省略，不拿空建议占位。

### 7. Conclusion（要点，100–150 词量级）

- 一段话收回关键步骤，重述从起点到结果。
- 下一步：相关 How-to、站内已有篇、或「要规格 / 要报价 / 要样品」。
- 不用「In conclusion, doing the thing is important」这类空收。

### 8. Semantic keywords

- 目标 30–50 个，一行一词，来自本轮搜索与相关问题。
- 三组：核心动作、限定/场景、问句或长尾。
- 不够则少写并标缺口，不重复 how to 或近义词凑数。

## 排版给下游

- 短段、可扫读；复杂步建议配图或编号图。
- 需要无障碍处只标记「此处需 alt / caption」，不在大纲里写假图片说明。

## 约束

- 关键词在 H1 出现一次即可，不在每步标题重复。
- 读者背景以本轮受众为准；未说明则按该任务的最低必要知识写，并标明「受众背景未在上下文出现，暂用」。
- 语气跟上游规范，不跟本模板的教学口吻走。
