# 客户画像分析 — 教学例子

> 仅供理解，禁止引用到输出。

本文全部例子都是教学支架，禁止把原文写入任何交付物。

形状借自买家人格调研的栏目顺序（是谁 → 钱怎么赚 → 决策链 → 自称/检索词 → 换与留 → 风险与耗时 → 邻层摩擦 → 供应商边界），不是某市场的真实名单。

## 切开：双闸与中间带

> 仅供理解，禁止引用到输出。

输入把「安装商」写成一条 → 成稿应拆执照层：进行业名册的闸，与并网/完工登记的闸，常常不是同一道。写成统一法律身份 → 重写。

输入把「工商业」当一条、只标容量口号 → 成稿应标供给变薄的中间带：对大户专班太小、对门店工匠太大。找不到这道缝则该条标 unverified，不拿「商业客户」凑数。

输入把同一组织里的规划席与采购席合成一条 → 成稿应写两道闸：商务闸（价、窗、条款）与技术闸（证书、图纸、兼容证据）；技术闸可否决商务闸。只满足其中一道的策略 → 重写。

批发平台注册表若把安装商 / 项目承包 / 转售商分成不同选项，那是切开证据，不是默认五条 ICP。

## 痛点写法

### 空泛 vs 可追溯

> 仅供理解，禁止引用到输出。

不要写「成本压力」或「在意质量与价格」。要写到来源里的机制，再接到采购决策。形状：〔该层钱怎么赚或哪道闸卡住完工〕→〔谁的 KPI 受损〕→〔因此选供应商时卡住什么〕→ URL。

- 门店工匠：材料价往往是利润载体不是成本中心；「更便宜」可能在打他的利润中心。改写成来源里的加价/工时机制，不要写「价格敏感」。
- 中间带安装商：第一交付物常是客户侧负荷/计量数据；电网与许可若被来源标成关键路径，痛点接到拿不到数据就无法报价，不要写「需要更好的设备」。
- 规划席：卡在供应商交得出的文件界面，不要写「方案专业」。
- 采购席：报价有效期是对方固定总价合同上的风险工具，不是客套；不要写「要便宜一点」。

数字只从来源抄，来源没有就写「未在来源出现」。冲突区间不要平均。

## 单条 ICP 块的形状

### 持证门店安装商（示意）

> 仅供理解，禁止引用到输出。

```markdown
### 1. 持证门店安装商（Licensed Trade Installer）

#### Overview
- 把部件装进客户现场的完工交付，不转售给同行
- 供应链下游、按单采购；业主同时是买家、技术责任人与报价人
- 进名册与并网完工常是两道闸；不要写成单一执照
- company_size / geographic_focus：只写本轮来源里有的

#### 痛点分析
- 材料价是利润载体：来源写明的加价/工时机制与谁的 KPI，附 URL
- 手头活要当天能装完；缺一件附件会停在客户现场
- 没有时间做结构化比价；换供是按品类拆篮，不是一次性翻户
- buying_criteria：可追责文件与当场能用，先于目录价
- decision_makers：业主本人；后台只执行、不拍板。KPI 是完工与返工工时，不是采购节省额

#### 销售策略
- **Outreach**: 第一封只对应该手头活的可核验符合项，不群发目录、不做比价表
- **Value Proposition**: 强调可追责的选型与投诉路径，不强调「更低材料价」，也不写「我们全包安装」
- **Objection Handling**: 「已有供货商」→ 问哪一类品会拆出（急件/重件 vs 常备小件），不要劝他整户搬家
- **Relationship Building**: 一次履约记录 → 指名联系人 → 再谈框架；不要从课程目录开场
- priority: P0
```

上面是块形状，不是某品类的真实结论。交付物必须换成产品上下文里的品类、市场与本轮来源。

## 换名测试

### 门店工匠 vs 中间带工商业

> 仅供理解，禁止引用到输出。

两条画像若都写「用冷邮件讲质量、灵活起订、快速发货」，换名后策略不变，判定失败。

门店工匠应落到：业主即买家、地理优先、手头活要可追责文件、材料加价养活工时；首触不要做成比价表。

中间带应落到：委员会、数据先于硬件、对大户太小对门店太大、现场席对采购席的否决。

规划席 vs 采购席：前者要可挂进证书链的文件包；后者要清单可过闸的字段与有效期。Outreach 的说法、异议和关系动作必须能分清是哪一条。

## 不要进主名单

> 仅供理解，禁止引用到输出。

自己已是分销层时，二阶转售商是邻层或对手席，不是客户。输入把它写成 ICP → 成稿应标排除并写原因，不要用「渠道伙伴」塞进主名单。

买家不用的外人学名不要当 ICP 英文名：对方自称承包商、招标与并网申请也写承包商，页面却写「项目开发商」→ 改成对方自己的词。

供应商边界：不要把未持有的安装、出证、质保签发写成对该画像的动作。
