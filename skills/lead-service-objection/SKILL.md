# 异议处理（购买触发点）

把报价后的买家异议当成仍在谈的信号，写成可上场的双语应对（承认→重构→证据→转向），落到 `deliverables/lead/10-sales/objection-handling.md`。缺证据标缺口，不编造案例、ROI 或未持有的证明。

## 步骤

1. **共用规则**。读 `skills/marketing-playbook-standards/SKILL.md`。完成：能复述数据锚定、例子禁引用、产出根、工具写能力。

2. **输入**。读台账 `state/lead-status.md` 的 `product_context`（默认 `~/Documents/New/CONTEXT.md`；把 `~` 展开为主目录，不当相对路径）。原文不拷进本仓库。硬依赖：已批准的 `deliverables/lead/10-sales/quotation-strategy.md`，或用户本轮贴出的报价要点 + 异议原文。软依赖（有则读，不阻塞）：`deliverables/lead/10-sales/first-contact.md`、`deliverables/lead/01-icp/icp-analysis.md`、`deliverables/lead/04-market/competitor-positioning.md`。闸门口径见 `skills/lead-generation/references/dependency-graph.md`，本文件不另写审批流程。产品、买家类型、至少 1 条异议仍缺：先看用户本轮；仍缺则打开 `skills/lead-interview/SKILL.md`（存在则按其做），否则停并写缺口。完成：能指出产品、买家类型、已报价格结构、异议原文各依据哪一段。硬依赖缺失、无 `user_waiver`、用户也未贴报价要点与异议 → 停，不编报价、不编买家原话。

3. **锁定四项**。从已读材料填四格，不另开问卷：① 所售产品与关键规格（价格区间只取上下文或报价稿）；② 买家类型（取 ICP / 产品上下文，不预设渠道角色）；③ 本买家点名的异议，最多取杠杆最高的 3 条；④ 竞品弱点（只取竞品稿、报价稿或用户本轮，不编质量事故）。完成：四格都有值或已标「未在上下文出现」；至少 1 条可回溯到买家原话或用户确认。

4. **查证**。用网页搜索查证该品类 B2B 采购常见异议、进口/交期/MOQ/质量抱怨；需要原文则抓取指定 URL。查询用产品上下文的品类与买家类型，不锁产地。品类对不上时可用相邻品类，必须标明外推。多条异议需要隔离时 dispatch a subagent, else do it inline；默认 inline。搜索不可用：用户已给异议原文则继续写话术，禁止写行业统计或「研究证明」；用户未给异议则停并写缺口。完成：有搜索日志；引用的模式或数字能回溯 URL 与访问日期，或已标缺口。

5. **撰写五件套**。按「写法」写出：Top 3 Objection Responses、Trust Narrative、Value Reframe、Visual Asset Idea、Embedded Lock-In。每条应对走承认→重构→证据→转向；证据与数字只来自产品上下文、报价稿、用户本轮或本轮已抓取页。凑满 3 条时，用户未点名的用查证到的品类模式补，并标明「品类常见、非本买家原话」。用户只给 1 条且搜索不可用：只写那 1 条，其余在缺口列出，不算全量完成。完成：五件套齐全或缺口已列；每条已写应对都有 EN + CN、可核验证据格、转向问句、心理原理；教学支架原文零出现。

6. **落盘** `deliverables/lead/10-sales/objection-handling.md`。完成：文件非空；断言满足或已声明未全量；未执行下游首单、未写成九场景心理分析。

## 写法

异议是购买信号，不是拒绝。沉默才更危险。价格异议表示在比；质量异议表示被伤过；交期异议表示有真实窗口；MOQ 异议表示库存或试单风险；已有供应商表示在探缺口。先承认再重构：驳回（「价格很合理」）会触发防守。

**四拍（每条异议都走完）**

1. 承认 — 表明听见了，不辩解。
2. 重构 — 从成本/风险转到价值/结果；写出买家「真正在说什么」。
3. 证明 — 一条对方能核验的证据（检测、批次数据、交期记录、报价稿里已写的条款）。空话（great quality）不算。
4. 转向 — 一个真问句，把异议收成下一步（比的是单价还是到岸后成本、现供哪一段在痛）。禁止反问攻击。

应对正文 2–3 句；先 EN 后 CN，中文是能上场的销售口吻，不是直译。补一句心理原理（为什么这四拍对该类型买家有效）。不同买家类型不共用同一套句子。

**Trust Narrative**

一条可回溯的真实路径：起初顾虑 → 决定往下走 → 结果。数字必须能指回上下文、报价稿或已抓取页。没有案例：仍保留结构，数字格写「未在上下文出现」，不编匿名厂名。全量完成至少 1 个可回溯数字。

**Value Reframe**

从单价转到总拥有成本：退货、延误、再采购、质量波动。12 个月差额只在两边数字都有来源时才算；否则写公式 + `[待补充]`，禁止填假的每件差额。用买家的词，不用供应商自评。

**Visual Asset Idea**

只出 **一个** 用户能做出来的视觉物：规格对照清单、跌落/耐久录像、包装前后对比、QC 照片序列。选与主异议直接相关的那一个。做不到的方案不要写。

**Embedded Lock-In**

协作交付物，在解决该异议的同时提高切换成本，读起来像增值服务。质量→可共检的节点或照片节奏；价格→报价稿里已有的量阶，不新开让价；交期→可共享的排产日历；MOQ→上下文允许的混箱/试单；已有供应商→对照卷宗 + 试单协议。禁止惩罚性锁客。

## 例子

> 仅供理解，禁止引用到输出。

形状借自渠道摩擦（已有供应商、质保路由、配额）和备线定位，不是某批发商品牌原句或论坛用户名。订货疑虑只清本单卡点，不种新问。

输入写「你们比现供贵」→ 成稿应承认差价看得见，重构到报价被中途改价打废、退货再采购的总拥有成本；证据只取上下文。不要先让价，不要写「价格很合理」，不要把锁价天数或到货日写进话术。收尾问现在比的是单价还是到岸后成本。

输入写「我们已经有供应商了」→ 成稿应把首单写成备线开口，不问「为什么换掉现供」。问哪几条线可以先放进来、会不会打乱现供的年量条件。不要写成换商战役，不要编现供质量事故。

输入写「坏了你们就推给厂家」→ 成稿应承认买家怕索赔被踢皮球，重构到谁承接工单、谁按厂家条款跑协调。证据只写上下文已有的协调能力。不要自称制造商、备件库或自有质保承保人。

输入写「旺季分不到货」→ 成稿应承认配额是留下现供的理由，把异议收到「哪条线需要第二来源」。不要用仓位或时效当卖点；上下文没有可核验交期就写「未在上下文出现」。

锁客必须解答该条异议。质保担忧对应可共检的工单节点，不是合同罚则；已有供应商对应对照卷宗加试单，不是排他条款。只有上下文确有的能力才写进交付物。本节句子不得进入交付物。

## 易错

- 没读报价稿或产品上下文就出话术，或编造买家原话凑满 3 条。
- 驳回异议，或价格异议第一句就是让价。
- 证据写「质量很好 / 客户都很满意」，没有可核验来源。
- 编造案例、不良率、ROI、未持有的检测或匿名成功故事。
- 把品类常见异议写成「该买家说过」。
- 采购、品牌方、经销商、电商转售用同一套句子。
- 转向问句是反问攻击，或只有中文、只有英文。
- 锁客像惩罚或隐瞒的切换陷阱；视觉方案用户做不出来。
- 把本文件当 `lead-buyer-psychology` 的九场景分析，或当报价/产品知识生成器。
- 搜索不可用仍写「研究证明」或行业统计。
- 把 skill 例子原文写入交付物。
