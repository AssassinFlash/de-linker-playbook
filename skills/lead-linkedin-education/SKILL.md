# LinkedIn 教育帖（Structure 6）

先头脑风暴 2–3 条该 ICP 能立刻执行的技巧，再按 Structure 6 写一篇教育型 LinkedIn 帖，落到 `deliverables/lead/08-linkedin/`。缺证据标缺口，不编造。本 skill 只产帖稿，不代为发布。

## 步骤

1. **共用规则**。读 `skills/marketing-playbook-standards/SKILL.md`。读 `skills/lead-generation/references/linkedin-post-guidelines.md`（篇幅、钩子、CTA、标签、四种风格、软广）；不要把该文件抄进本 skill 或交付物。完成：能复述数据锚定、例子禁引用、产出根、工具写能力；能复述钩子须落在折叠前、结尾恰好一个 CTA、3–5 个标签、产品句可删。

2. **输入**。产品与公司事实读事实源入口 `docs/fact-sources.md`，按其「什么问题查哪个源」取证；查不到标〔未证实〕，按没有处理。硬依赖：已批准的 `deliverables/lead/01-icp/icp-analysis.md`。软依赖（有则读，不阻塞）：`deliverables/lead/05-usp/usp-strategy.md`、`deliverables/lead/05-usp/product-knowledge.md`、`deliverables/lead/08-linkedin/topic-research.md`。用户本轮给出的品类、受众、主题、技巧要点或 CTA 一并用作本轮输入，来源记「用户本轮」。品类、目标海外受众或至少一条可教育的痛点仍缺：先看本轮消息；仍缺则打开 `skills/lead-interview/SKILL.md`（存在则按其做），否则停并写缺口。不要在本文件另写问卷。完成：能指出品类、受众、痛点各依据哪几条；原文不拷进本仓库。硬依赖缺失、用户本轮也未给出对应受众与痛点、且无 `user_waiver` → 停。

3. **查证**。用网页搜索查证该类买家在该品类上的常见失误、选购问题或 how-to 缺口；需要原文则抓取指定 URL。帖中将点名的程序、标准、认证核验方法或数字：必须先搜到再写。搜索意图与降级见 `references/structure-6.md`；日志格式见 `skills/lead-generation/references/search-protocol.md`。搜索不可用：若还要发明程序或「常见错误」→ 停并写缺口；若用户已给出完整技巧且帖中无程序/标准/统计断言 → 可成稿，日志写「本轮未检索；帖中无程序/标准/统计断言」。禁止为凑次数空搜。禁止把搜到的他人帖原文写入交付物。需要隔离时 dispatch a subagent, else do it inline。完成：将写入帖子的程序/标准/数字有 URL 或已决定不使用；`## 搜索日志` 有行。

4. **头脑风暴**。读 `references/structure-6.md` 的卡片格式与 tip 质量测试。产出 **2–3** 条互不重复的教育技巧（不是行业趋势，不是出口合规流程）。优先用已批准话题研究里偏 how-to / 选购 / 维护的条目当种子，不够再补。每条含：Suggested Topic、Key Content Points、Why this ICP。用户本轮已指定唯一话题 → 仍写该条卡片，候选可少到 1，并注明「用户本轮已指定」。证据不够就少写，不拿跨品类空话凑满 2–3。完成：每张卡片能通过 tip 质量测试；能指回 ICP 痛点或本轮查证。

5. **成稿**。选题：用户点名 → 用该条；本轮能问则只问一句选哪个；用户已说直接做、或本轮不能问 → 取卡片 1，交付物写「选题未经用户确认」。按 Structure 6 顺序写英文帖：Hook → Tip → Why (Benefit) → Resource offer → CTA，然后 3–5 个标签。骨架与「Why this matters」映射见 `references/structure-6.md`。用户点名微博客 / 故事叙事 / 滑梯式 / 直销节奏之一时，成稿后再按共用规范改语气与结构，不改核心信息。面客语种以产品上下文为准，缺省英语；策略说明用本轮语言。完成：一篇可复制正文；五段齐全；钩子落在折叠前；恰好一个 CTA；产品句 0–2 句且删掉后帖子仍有用。

6. **质检并落盘**。对照共用规范出门清单与本文件清单后，写入 `deliverables/lead/08-linkedin/education-post.md`。不代发布：`publish_status: copy_only`。过证据闸、审稿到 `operator_ok` 后由操作者亲手发，发完走执行登记（`skills/marketing-execution-log/SKILL.md`）。完成：主文件非空；候选与成稿都在；教学支架原文零出现。

## 默认

- 产品与公司事实读事实源入口 `docs/fact-sources.md`，按其「什么问题查哪个源」取证；查不到标〔未证实〕，按没有处理；不在本仓库另存档案。产地、目标市场以产品上下文为准，不预设某一出口国。
- 查证用网页搜索；需要原文时抓取指定 URL。不并列搜索引擎菜单。搜索不可用则按步骤 3 降级，不编造。
- 本帖类型是可执行技巧 / 选购指南 / 维护 how-to。宏观趋势走 `skills/lead-linkedin-authority/SKILL.md`（文件存在时）；出口法规、物流、市场准入走 `skills/lead-linkedin-expertise/SKILL.md`（文件存在时）。不要用本文件写揭谣、FAQ、个人故事或幕后厂拍。多平台日历或战役走 `skills/marketing-social-content/SKILL.md`（文件存在时）；选题卡走 `skills/lead-linkedin-topic-research/SKILL.md`（文件存在时）。
- 篇幅、钩子、CTA、标签、四种风格、软广只认 `skills/lead-generation/references/linkedin-post-guidelines.md`。
- 一条帖子只讲一条技巧。价值在前，产品在后；去掉产品句后仍应独立有用。
- 单篇 inline 做完；多 ICP 需隔离时 dispatch a subagent, else do it inline。
- 产出只进 `deliverables/lead/08-linkedin/`。Markdown only，不写表。
- 验证—审查—审批走 `skills/lead-generation/references/orchestration-protocol.md`，本 skill 不代替审批、不代替发布。

## 写法

- 技巧必须具体到读者能照做。空话（选优质供应商、沟通要清晰）不写。
- 先写 tip 本身（步骤或要点列表，最多 5–7 条），再写为什么对该 ICP 重要（省时间、省钱、避延误、降风险——只接已批准痛点或本轮查证，不发明挑战）。
- Resource offer 把自己放在「需要时可以再问」的位置，不堆规格、不写成目录页。
- CTA 用共用规范四类之一；用户未指定时默认评论型经验问题，并标明「CTA 未经用户指定」。
- 短段、段间空行；专业但像人。不写 I'm excited to share / In today's competitive landscape。
- 数字、认证、核验步骤、法规名：上下文或已抓取页里有才写。没有就换不依赖该事实的技巧，或标缺口后删掉该句。
- 同一帖不混用两种面客语种。品类名一篇一译并锁定。
- 专家买家不从零解释基础术语；新进口商不堆只有工程师能用的缩写。以 ICP 为准。

## 例子

> 仅供理解，禁止引用到输出。

输入写「帮买家少踩坑」。形状借同档批发店 FAQ 的问句分桶：先锁**一类**买家会原话问出来的检查（订货报价、到货核验、货损退货、质保对接、技术一线），再写成该 ICP 能立刻勾选的步骤，并解释跳过会卡在哪一类项目风险。不要写「选择高质量供应商」，不要多桶并进一帖，也不要把厂家诊断脚本或店里的时限金额塞进帖子。产品句最多一两句，删掉后技巧仍成立。更多形状见 `references/examples.md`。不要把本节句子粘进交付物。

## 易错

- 没读已批准 ICP 就发明「买家常犯的错」。
- 把教学例子或搜到的他人 LinkedIn 帖原文写入交付物。
- 写成行业趋势帖或出口合规帖，走错相邻 skill。
- 一条帖子塞多条不相关技巧。
- 技巧其实是伪装产品推销；删掉产品句后无剩余价值。
- 程序、认证核验方法或统计未查证就写成事实。
- 为凑满 2–3 条用跨品类空话。
- AI 代发或代发布（不论是否配置工具、用户是否要求），或把成稿当成已发出。
- 忽略共用规范的折叠前钩子、单一 CTA 或标签组合。
- 终稿残留未解释的 `{{...}}`，或把 `[待补充]` 假装成已核实步骤。
