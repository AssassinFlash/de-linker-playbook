# Structure 6：教育帖骨架

条件：写教育型 LinkedIn 帖、出 tip 卡片、或判断一条建议算不算 tip 时读本文。执行顺序与完成条件以 `SKILL.md` 为准。篇幅、钩子、CTA、标签、四种风格、软广：读 `skills/lead-generation/references/linkedin-post-guidelines.md`，本文不重复。

## 边界

本帖：可执行技巧、选购标准、维护 how-to。读者看完能做一步。

不是：

- 宏观行业趋势或「越来越多买家选择 X」的市场叙事 → `lead-linkedin-authority`
- 出口法规、物流、HS、认证准入、贸易单据 → `lead-linkedin-expertise`

一条帖子只承载一条技巧。多主题拆成多帖，不塞进同一篇。

## 头脑风暴卡片

目标 2–3 条，互不重复。用户本轮已指定唯一话题时可以只有 1 条。

每条必填：

| 字段 | 要求 |
| --- | --- |
| Suggested Topic | 一句说清主题，能当帖子标题方向 |
| Key Content Points | 可执行要点或步骤，不是口号 |
| Why this ICP | 接到已批准痛点或本轮查证的一句话 |

可选：该条是否依赖某条程序/标准（依赖则步骤 3 必须查证）。

有 `deliverables/lead/08-linkedin/topic-research.md` 时，先取其中 how-to / 选购 / 维护类条目当种子，不够再补；不要另起一套与已批准话题无关的清单。

## Tip 质量测试

通过全部才进入候选：

1. **真有用**：能省时间、省钱、或少一次返工/延误。做不到这三者之一 → 淘汰。
2. **具体**：读者能照着做。对照形状（禁止把对照句写入交付物）见 `examples.md`。
3. **一篇一事**：卡片里不要并列两条互不依赖的技巧。
4. **该 ICP 做得到**：不假设上下文未出现的设备、权限或专业执照。
5. **不是软广**：去掉任何产品句后，要点仍然成立。
6. **不是空话**：行业无关的「沟通要清晰 / 选择靠谱供应商 / 注意质量」直接淘汰。

## Structure 6 顺序

编号与骨架必须保留，成稿按此顺序，不要重排、不要合并段落职责。

1. **Hook** — 用共用规范允许的开篇之一，对准这条技巧的主题与该 ICP。必须落在折叠前。
2. **Tip** — 把技巧本身写清楚。步骤或要点用列表，最多 5–7 条。此处给做法，不给产品。
3. **Why (Benefit)** — 说明照做之后，对该受众意味着什么。映射见下一节。
4. **Resource offer** — 表示可以再帮一把（答疑、对照一份对方的清单），不堆规格、不贴目录。
5. **CTA** — 恰好一个，取共用规范四类之一。

其后才是 3–5 个标签（组合口径见共用规范；品类标签取产品上下文的品类字段）。

成稿时先写 Hook，再根据已选 tip 与受众写出 Why，再按上面五段组装。不要先写产品再倒推技巧。

## Why this matters

Why 段必须接到**该 ICP 已有**的挑战或目标，而不是作者觉得重要的行业套话。

允许的连接方向（有证据才用，不 invent 一条）：

- 避延误
- 降成本或避免隐性成本
- 满足其必须遵守的要求（仅当该要求已在上下文或查证中出现）
- 提高其内部效率或一次通过率
- 降低项目或声誉风险

写完自问：这句 Why 能指回 ICP 哪一段，或搜索日志哪一行？指不回 → 重写或换 tip。

## 查证意图

默认Apify 搜索；需要原文则抓取指定 URL。不为凑次数。

| 何时 | 查什么 |
| --- | --- |
| 从零头脑风暴 | 该类买家在该品类上的常见失误、选购问题、公开 how-to 缺口 |
| 卡片点名了程序、标准、核验方法 | 该方法或标准是否公开存在；核验路径是否写得出来 |
| 卡片含数字 | 数字的出处与年份 |
| 可选 | 公开讨论里是否已有高度同质的 tips 帖——用来避开抄袭，不用来复制 |

查询里的花括号是字段，不是交付物句子。品类与市场取产品上下文和已批准 ICP。

```
"{product_niche}" common mistakes buyers {target_market}
"{product_niche}" tips for importers {target_market}
"{product_niche}" how to choose OR selection criteria
```

程序/标准核验不够时，换一条不依赖该事实的 tip，不要把未核验步骤写成事实。

## 缺口

- 硬依赖 ICP 缺失且无本轮受众/痛点、无 `user_waiver` → 停，不成稿。
- Apify 修复与替代取证后仍不可得且还要发明「常见错误」或未核验程序 → 停。
- 2–3 条凑不满：按实有条数写，缺口注明「未用空话补候选」。
- 用户未选且本轮不能问：用 Tip 1，标 `selection: default_first_unconfirmed`。
- 用户未指定 CTA：默认评论型经验问题，标「CTA 未经用户指定」。
- 只产帖稿，AI 不代发布；发帖由操作者亲手做。
