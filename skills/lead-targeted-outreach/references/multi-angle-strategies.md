# 多角度邮件策略

条件：extended 模式选角度、排序列或写发送节奏时读本文。default 三封不必读。完成条件以 `SKILL.md` 为准。

## 目录

## 选用

按这家公司的调研选角，不按喜好凑满九个。缺该角所需证据就不用。

| angle | 适用 | 不用 |
| --- | --- | --- |
| curiosity_hook | 调研里有对方尚未写进常识的具体信号 | 只有行业套话 |
| industry_insight | 有带来源的趋势，且能接到这家公司 | 「洞察」是公开常识 |
| use_case | 产品上下文有真实同类客户结果 | 需要编案例 |
| roi_breakdown | 有可指回的成本或效率数字 | 数字未在来源出现 |
| objection_handling | 调研或 ICP 写明了该角色的反对点 | 在猜反对点 |
| competitive_positioning | 调研知其现行做法或供应商类型 | 不知其现在怎么买 |
| social_proof | 产品上下文有可指回的证言、客户类型或认证 | 证明弱或与对方无关 |
| value_add | 上下文里确有可另寄的资料（规格、清单、样品政策） | 所谓资料其实是推销页，或资料不存在 |
| breakup_nudge | 序列末封，且前面至少已有两封 | 第 1 或第 2 封 |

用户点的角度少于封数：按下方推荐顺序补不重复的角。仍不够则减封，并在策略概述写缺口。点的角度多于封数：按推荐顺序取前 N 个，Break-up 若入选则固定末位。

## 九个角度

每角三至四行。第 1 行必须能指回调研或产品上下文；数字与证言规则同 `SKILL.md`。

### 1. curiosity_hook

- 目的：用对方世界里的具体信号打开一个需要闭合的问题。
- 结构：具体信号 → 对该公司的含义（一句）→ 低压 CTA（是否与其所见相符）。
- 语气：同行、略带锋芒、真在问。
- 不用：无来源的行业百分比。

### 2. industry_insight

- 目的：表明你读过他们所在的行业，而不是在群发。
- 结构：有来源的趋势 → 对同类公司意味着什么 → 一句能力相关（须 strong/moderate）→ CTA（是否看别人如何应对）。
- 语气：对等，不说教。

### 3. use_case

- 目的：用真实结果证明可落地。
- 结构：同类公司类型 + 同类挑战（须能指回上下文）→ 做了什么（短）→ 结果（有数字才写数字）→ 接到调研里的一条细节 → CTA（可讲细节）。
- 语气：叙事、具体、结果在前。

### 4. roi_breakdown

- 目的：把价值说成可核验的账。
- 结构：其成本中心或效率缺口（来自调研）→ 上下文里的对比数字（写来源）→ 按其已披露体量做**区间**而非精确承诺 → CTA（是否按其工况算一版）。
- 语气：分析、无鼓吹。无数字则禁用本角。

### 5. objection_handling

- 目的：在被忽略之前点破已知反对点。
- 结构：直接点名反对点 → 承认合理 → 用上下文证据对冲 → CTA（同类买家怎么处理）。
- 语气：承认、举证，不辩赢对方。

### 6. competitive_positioning

- 目的：用结果区分，不点名攻击。
- 结构：现行做法里已取证的摩擦（不写未证实的竞品商号，除非调研已写明）→ 我方做法的结果差异（一条 USP）→ 与其处境相关的一条优势 → CTA（是否看对照）。
- 语气：有把握、不贬低。

### 7. social_proof

- 目的：让第三方说法承担信任。
- 结构：谁在用（行业 / 公司类型 / 区域，须在上下文）→ 他们怎么说（转述须能指回）→ 与对方处境的关联 → CTA（是否介绍证明人，仅当上下文允许）。
- 语气：克制，让证据自己说话。

### 8. value_add

- 目的：先给后求。只提供上下文里已有的资料。
- 结构：点名那份资料 → 里面有什么、为何对其有用（不是销售页）→ 无附加条件可另寄 → CTA（是否寄出）。
- 语气：帮得上、零压力。
- 可寄：规格对照、合规清单、样品政策、已有的基准表。上下文没有对应文件则禁用本角，不临场发明「审计报告」。

### 9. breakup_nudge

- 目的：礼貌收束，用结束制造最后一次回应窗口。
- 结构：说明这是最后一封 → 一句核心价值（已在前序出现过）→ 门仍开着 → 低压 CTA 或无 CTA。
- 语气：短、尊重、不愧疚。

## 序列结构

推荐顺序，保证叙事弧，不保证每家都走满。

**3 封 extended**（用户要 extended 但未给 N 时，若只要三封，仍用此序，不要与 default 弧混名）：

1. curiosity_hook 或 industry_insight
2. use_case 或 roi_breakdown
3. breakup_nudge

**5 封**（用户说 extended 且未给 N 时的缺省）：

1. curiosity_hook
2. industry_insight
3. use_case 或 social_proof
4. value_add
5. breakup_nudge

**7 封及以上**：

- 先软（curiosity_hook、industry_insight）
- 再证明（use_case、roi_breakdown、social_proof）
- 再阻力（objection_handling、competitive_positioning）
- 再给予（value_add）
- 末封 breakup_nudge

缺省封数：用户说 extended 但未给 N → 5 封，再按上表能用的角裁剪。

## 发送节奏

默认表。时区取调研中的总部；没有则 `send_window` 写「时区未在调研出现」，只保留 Day 偏移。工作日上午；调研或本轮写明的公开假期才避开，不编当地作息。

| email | day_offset | notes |
| --- | --- | --- |
| 1 | 0 | 收件人时区工作日上午 |
| 2 | 3 | 同一线程（回复第 1 封） |
| 3 | 5 | 同一线程 |
| 4 | 7 | 新线程、新主题 |
| 5 | 10 | 跟第 4 封同一新线程 |
| 6+ | 14+ | 间隔拉长；每 3 封换一次线程 |

`day_offset` 是距第 1 封的日历天数（累计，不是距上一封）。写入 `outreach.md` 时写成 `Day 0 / Day 3 / Day 5` 这种具体值，不写「隔几天」。
