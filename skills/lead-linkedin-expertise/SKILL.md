# LinkedIn 专业帖（市场准入）

针对指定海外区域，把可核验的出口与市场准入流程知识写成 Structure 12 LinkedIn 帖，落到 `deliverables/lead/08-linkedin/`。只产帖稿，不发布。法规、认证与代办能力不编造。

## 步骤

1. **共用规则**。读 `skills/marketing-playbook-standards/SKILL.md`。完成：能复述数据锚定、例子禁引用、产出根、工具写能力。

2. **输入**。读台账 `state/status.md` 的 `product_context`（默认 `~/Documents/New/CONTEXT.md`；把 `~` 展开为主目录，不当相对路径）。硬依赖：已批准的 `deliverables/lead/01-icp/icp-analysis.md`。软依赖存在则读：`deliverables/lead/08-linkedin/topic-research.md`、`deliverables/lead/05-usp/usp-strategy.md`、`deliverables/lead/05-usp/product-knowledge.md`。用户本轮给出的品类、目标区域、受众、准入主题或 CTA 视为本轮输入，来源记「用户本轮」。核心三项：品类或产品线、目标海外区域、该区域内的受众。仍缺则打开 `skills/lead-interview/SKILL.md`（存在则按其做）；不存在则停并只要这三项，不在本文件另写问卷。原文不拷进本仓库。硬依赖文件缺失、用户本轮也未给出对应全文、且无 `user_waiver` → 停。完成：能指出品类、区域、受众、合规痛点各依据哪几条。

3. **查证**。读 `references/expertise-research.md`。用网页搜索查该品类进入该区域的准入卡点，并对将写入帖文的每一条法规、标志、税则、单据或贸易术语抓取或核到现行页。搜索不可用则停止并写缺口，不编造合规句。禁止为凑次数空搜。禁止把他人 LinkedIn 原文写入交付物。多条法规需隔离时 dispatch a subagent, else do it inline。完成：每条拟用法规句有 URL 与访问日期；公司代办/出证/注册只能来自上下文或用户本轮。

4. **选题**。从查证结果收成 1–2 个具体专业领域。用户本轮已点名主题则收窄该主题，不另起无关领域。每个候选必须写清：领域名称、为何只在该区域成立、可执行知识或流程、公司是否真做（有/无/仅配合提供资料）。用户已选定或点名「直接写 / 先跑一遍」→ 取证据最强且公司能力对得上的一条，`selection_source` 记 `user` 或 `agent_pick`。否则把候选写入交付物「选题」节并在回复中列出，等选定后再写帖文；未选定不算全量完成。完成：选定领域满足 `references/expertise-research.md` 的可核验专业测试与公司能力闸门。

5. **起草**。读 `references/structure-12.md` 与 `skills/lead-generation/references/linkedin-post-guidelines.md`（只核对其清单，不复制其正文）。按 Structure 12 五拍写英文帖：Hook → Knowledge → Simplification → Benefit → CTA，然后 3–5 个标签。用户点名四种风格之一时，成稿后再改语气与分段，不改已核验事实。面客语种缺省英语；策略笔记用中文。完成：五拍齐；钩子含领域与区域；法规句能指回来源表。

6. **质检并落盘**。按清单自检后写入 `deliverables/lead/08-linkedin/expertise-post.md`。本 skill 不发布；`publish_status: copy_only`。用户自行发布，或经用户已配置的工具发布。付费发布须先告知并获准。完成：主文件非空；含选题、可复制英文帖、策略说明、来源与搜索日志；教学例子原文零出现。验证—审查—审批走 `skills/lead-generation/references/orchestration-protocol.md`，本 skill 不代替审批、不代替发布。

## 默认

- 产品事实只读台账 `product_context`（需要参数再读 `~/Documents/New/fact-base/`），不在本仓库另存档案。出口产地、是否做某项认证或代办，一律以上下文为准，不预设某一出口国。
- 查证用网页搜索；需要原文时抓取指定 URL。不并列搜索引擎菜单。搜索不可用则停止合规句并写缺口，不编造。
- 进度只认台账。产出只进 `deliverables/lead/08-linkedin/`。只出 Markdown，无表。
- 分析与缺口用本轮语言（缺省中文）；帖文、标签、CTA 用买家语言（缺省英语）。同一段不中英混排。
- 本帖写贸易流程知识（税则、单据、认证标志、贸易术语、信用证、海关、出口包装、区域认证怎么走）。产品选购技巧走 `skills/lead-linkedin-education/SKILL.md`；行业趋势走 `skills/lead-linkedin-authority/SKILL.md`；工厂现场走 `skills/lead-linkedin-behind-scenes/SKILL.md`；区域使用/气候障碍走 `skills/lead-linkedin-market-challenge/SKILL.md`（文件存在时再打开，不在本步执行）。
- 发布仅当用户本轮要求且已配置相应工具；否则只产帖稿。
- 数字、处罚、费率、证书编号、客户名：上下文或本轮查证有才写。

## 写法

- 把公司当准入搭档来写，不当纯供货清单。内部知识必须译成该区域买家的可感结果。
- 专业领域必须具体到可点名的制度或步骤。区域名出现在钩子。换一个市场句子仍完全成立 → 太泛，收回重写。
- 简化句能删则帖子仍有用。禁止「Our product features X」式硬广。
- 法规只写已核验且未过期的口径；策略笔记写来源日期。不确定就删该句。
- 不把买家义务写成我方已代办。上下文没有的注册、出证、熏蒸、制单，不写进简化拍。
- 短段、1–2 句一段；权威、可执行、对买家说话。篇幅、表情、软广上限以共用规范为准。

## 易错

- 没读已批准 ICP 或产品上下文就发明区域痛点或代办能力。
- 把教学例子或他人 LinkedIn 原文写入交付物。
- 写成产品技巧、行业趋势或工厂参观，走错帖型。
- 用「我们懂法规」当 Knowledge 拍。
- 法规未核现行页，或把过期转载当现行口径。
- 把进口方义务写成我方已代办。
- 未配置发布工具仍发布，或把成稿当成已发出。
- 为凑搜索次数空搜，或搜索不可用仍写合规句。
- 终稿残留未解释的 `{{...}}`。
- 把共用规范全文粘进交付物。
