# 市场准入查证

条件：为本帖发现或核验出口/准入说法时读本文。执行顺序与完成条件以 `SKILL.md` 为准。搜索日志格式可与 `skills/lead-generation/references/search-protocol.md` 对齐；本帖以「每条法规句有来源」为完成条件，不以搜索次数凑数。

## 默认能力

默认用 Apify 搜索查证。需要原文、官方法规页或公告时，抓取指定 URL 的正文。Apify 修复与替代取证后仍不可得或关键页Apify 与替代取证仍不可得：停止，不把该法规写进帖文，缺口写明。不并列搜索引擎菜单。需要隔离多条法规时 dispatch a subagent, else do it inline。

## 必须查清的三类

1. **准入挑战** — 该品类进入目标区域时，买家或进口方实际会碰到的规则、单据、物流或认证卡点。
2. **点名规则的现行口径** — 帖子若出现某一法规、标志、税则、贸易术语或单据名，必须核到现行来源（官方、主管机构或该区域进口说明），记下 URL 与访问日期。
3. **公司是否真做** — 简化句里的代办、注册、出证、熏蒸、制单，只能来自产品上下文或用户本轮。上下文没有则不当成已提供的服务。

公开 LinkedIn 帖可用来听买家怎么叫这个问题，禁止把他人帖文写入交付物。

## 查询模板

花括号是字段，取产品上下文、已批准 ICP 与用户本轮，不把模板句抄进帖文。`{year}` 用本轮访问年。

```
"{product_niche}" export requirements {target_country} {year}
"{product_niche}" import regulations {target_country}
"{specific_regulation}" requirements {target_country} current
"{product_niche}" customs documents OR HS code {target_country}
"{product_niche}" certification OR conformity {target_region}
```

优先官方法规页、海关/标准机构、该区域进口指南。行业软文只作线索，法规句不以软文为唯一来源。

## 可核验专业（通过才进入候选）

候选领域必须同时满足：

- 绑在用户指定的那一个区域，不把「国际贸易」当区域。
- 能写出买家可执行的一步（该交哪份文件、该对哪个编码、该过哪道检测），而不是「经验丰富」。
- 该品类在该区域确实会碰到（有来源），不是把别的品类的认证套过来。

测法：把区域名换成另一个市场，句子仍完全成立 → 太泛，弃用或收窄。

## 公司能力闸门

| 上下文或用户本轮 | 帖子里可以写 |
| --- | --- |
| 写明代办 / 已注册 / 出具某文件 | 简化句可写我们如何经办该步 |
| 只写产品符合某标准、无经办描述 | Knowledge 可解释该标准；简化句只写如何配合提供资料，不写「我们办理注册」 |
| 未出现该法规或服务 | 换一条上下文确实在做的流程；或只写公开核对步骤，简化句标缺口且不声称代办 |

禁止把查到的「进口方义务」写成「我方已代客户完成」。

## 时效

法规会改。来源须能判断仍有效，或在策略笔记写明「据 [日期] [URL]，现行口径为…」。过期页、无法判断年份的转载，不得单独支撑帖文中的法规句。帖中不写无来源的「最新政策」年份或处罚金额。

## 缺口

- Apify 修复与替代取证后仍不可得该品类×该区域的准入点 → 不停编一个「常见法规」，停并写缺口。
- 规则名能搜到、现行页Apify 修复与替代取证后仍不可得 → 帖文不写该规则，或只写「以主管机构现行说明为准」并在缺口列出待核 URL。
- 公司能力对不上已选领域 → 改选候选，不编造代办。
