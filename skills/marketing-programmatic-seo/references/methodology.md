### 最小上下文

- 目录范围：材质、表面、尺寸、应用的真实组合，用于卡住页面上限
- 询盘最多的约 5 个国家或地区
- 公司所在地：地点页信任信号与 LocalBusiness 结构化数据
- 目标站点技术栈与 URL / 模板约束
- 已有产品、地点或应用页：必须保留、不得覆盖

缺项列缺口后停。

## 收集

默认一条能力：用网页搜索查证。需要原文时抓取指定 URL 的正文。搜索不可用则停止并写缺口，不编造、不并列多引擎菜单。用户已配置网页采集服务时，才用它抓公开页或动态页。

把产品上下文的品类、应用、材质、表面、目标市场代入下列意图；每条记下 URL、访问日期、摘录，并记录首页排名者、页面类型、URL 模式。证据够用或已写缺口即可停。

1. 制造 / 外贸场景下的程序化 SEO 做法（年份用当前，不编造历史流量）
2. 品类 + 目标市场 + supplier
3. 品类 + 上下文出现的每种应用
4. 品类内材质对比、表面对比（只查上下文出现的配对）
5. 品类 + 优先国家或地区
6. wholesale + 品类
7. custom + 品类 + manufacturer
8. 品类 + 公开单价或起订量
9. B2B 品类的模板页 / 规模化落地页
10. 制造供应商的可扩展内容页
11. B2B 地点落地页
12. 产品对比页模板
13. 该品类制造商的长尾检索模式
14. 目标站点技术栈上的 B2B 程序化页面约束（当前年份）

### 抓取

优先：

- 前 3 个竞品的产品或品类页
- 2 个竞品地点页或应用页
- 1 个目标渠道（以产品上下文为准）上的品类页，只用来观察分类法，不把渠道名写进方法正文

抽出：URL 模式、title / H1、内容区块、规格表、询盘入口、结构化数据信号。

### 目录挖掘

读产品上下文与已有表，必要时运行 shell 命令处理本仓库内的表：

- 真实变体矩阵：材质 × 表面 × 应用 × 尺寸（只含目录里有的组合）
- 各变体是否已有项目照片
- 各产品线的起订量、交期、价格带（上下文有才写）

### 数据下限

硬门（达不到就写缺口，不降格成猜测）：

- 变体矩阵来自实际目录
- ≥50 条长尾有真实 SERP 证据
- ≥3 个竞品程序化页面分析（URL 模式 + 内容结构 + 排名词）
- ≥4 种页面类型的 URL 模式建议
- 每种页面类型有目标站点技术栈上的实现路径

### 核验

- 搜索证据来自现场 SERP 或上游 `seo-audit-data.xlsx`，禁止虚构搜索量
- 竞品分析必须引用收集时打开过的 URL
- 变体矩阵必须反映真实目录
- 地点优先级来自询盘数据或 SERP，不猜
- 每个数据点带 `source`：URL、查询词或文件路径

## 分析

### 页面类型优先级

按收集结果取舍。B2B 目录的默认优先级如下，有反证则改，并写来源：

| 优先级 | 页面类型 | URL 模式 | 流量信号 |
| --- | --- | --- | --- |
| P0 | 地点供应商 | `/suppliers/[country]/` | 区域采购 |
| P0 | 应用 | `/applications/[use-case]/` | 项目阶段买家 |
| P1 | 产品 × 属性 | `/products/[variant]-[finish]/` | 设计阶段买家 |
| P1 | 材质或工艺对比 | `/compare/[a]-vs-[b]/` | 认知阶段 |
| P2 | 属性集合 | `/collections/[attribute]/` | 浏览阶段 |
| P2 | 词表 / 教育 | `/guides/what-is-[term]/` | 漏斗顶部 |

URL 模式必须适配目标站点技术栈的 slug、层级与模板上限，不能照搬上表。

### 变量库

只收录目录与证据里出现的值：

- 材质、表面、应用、尺寸
- 地点：询盘或 SERP 支持的优先市场，建议不超过 5 个先发
- 对比配对：材质对材质、表面对表面、采购路径对采购路径

每个变量：`variable_name`、`values`、`count`、`source`。

### 独特性

每个页面必须有实质不同内容，不是换词：

- **产品 × 属性**：规格、公差、项目照片、用途说明
- **地点**：该市场贸易条款、进口要点、本地项目或询盘、市场 FAQ
- **应用**：行业背景、典型项目用量、相关认证、推荐变体
- **对比**：并排表，含使用周期成本、维护、安装

同一页面类型下任意两页，H1、首段、规格表、项目照片或市场信息至少三处明显不同。

### 目标站点实现

为已确认的技术栈写实现说明，不把工作写成「交给开发」：

- 每种页面类型一个模板（命名按类型，如 `pseo-location`）
- 动态字段：品名、属性、材质、起订量、交期、目标市场（字段来自目录）
- URL handle：关键词可读、小写、连字符、禁止仅 ID 的 slug
- 批量创建：CSV 导入、站点管理接口、或生成脚本（以技术栈为准）
- 索引规则：有真实照片和规格的 index；薄组合 `noindex` 直到内容就绪

### 内链

Hub-and-spoke：模板页连回所属枢纽。

- `/suppliers/` → 各国地点页
- `/applications/` → 各应用页
- `/products/` → 各产品×属性页
- 交叉：产品页链到相关应用与属性集合

### 质量先于数量

带真实规格、照片和询盘入口的约百页，优于数千薄变体。扩规模前：

1. 每类先手工做 1 页
2. 核对真实照片、规格表、询盘入口都在
3. 检查近重复
4. 再生成该类型其余页面
5. 分批上线，不一次全发

## 交付

主文档 `deliverables/marketing/02-seo/programmatic-seo.md`，建议均须引用收集阶段来源。七个必需章节：现状诊断、批量页面矩阵、优先批次建议、平台实施方案、内容独特性策略、内部链接架构、Indexation 策略。

每种页面类型：URL 模式、估计页数、主关键词模板、变量数据来源、独特性方法。页数只按已核验维度的真实组合计算。

### 工作簿

从 `templates/pseo-page-matrix.xlsx` 复制到 `deliverables/marketing/02-seo/pseo-page-matrix.xlsx` 后填行。

**Page Matrix**（≥50 行）：`url_pattern`，`page_type`，`template`，`primary_keyword`，`search_evidence`，`variables`，`content_source`，`priority`，`source`

**Variable Database**：`variable_name`，`values`，`count`，`source`。至少覆盖上下文实际存在的材质、表面、应用、地点。

**Implementation Plan**：`batch`，`page_count`，`template`，`priority`，`estimated_traffic`，`status`，`source`。`estimated_traffic` 无 SERP 或上游表支持则写缺口，不填估计值。

### 附件（同目录）

- `page-templates.md` — 每类页面的结构：动态字段、规格表区域、询盘入口
- `data-matrix.md` — 材质 × 表面 × 应用 × 市场的真实组合表
- `url-structure.md` — URL 模式、示例路径、集合或列表设置；全部小写、连字符、无仅 ID slug，且符合技术栈约束
- `internal-linking-map.md` — hub 与 spoke 及关系
- `content-variables.md` — 按表面 / 地点 / 应用可复用、且已差异化的片段；每条有来源

每行或每条建议引用生成它的文件或查询。

## 反模式

1. 只换变量、没有独特规格 / 照片 / FAQ
2. 没有关键词证据就定 URL 模式
3. 忽略技术栈的页面数、slug、层级限制
4. 跳过竞品程序化页面分析
5. 近重复仍全部 index
6. 一次上线全部页面
7. 把本文件或其他行业页面原文写入交付物
8. 省略 `source`

## 质量闸门

- Page Matrix ≥50 行，每行关键词证据与 `source` 非空
- ≥3 个竞品程序化分析有真实 URL
- 变量库覆盖目录实际维度
- 每类有模板名、动态字段、批量方法
- 独特性按类型写清
- 内链标明 hub / spoke
- URL 模式小写、连字符、无仅 ID slug
- 模板含动态字段、规格表、询盘入口
- Indexation 区分 index 与 `noindex`，并说明站点地图分段
- 终稿无未替换的目录占位符、无教学例子原文
