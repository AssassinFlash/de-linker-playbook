## 采集

默认一条能力：用网页搜索查证。需要原文时抓取指定 URL 的正文。搜索不可用则停止并写缺口，不编造、不并列多引擎菜单。

### 本站漏斗体验

抓取并摘录：

1. 首页 — 价值主张、信任信号、主 CTA
2. 产品 / 品类页 — 规格、CTA 位置、询盘入口
3. 询盘 / 联系页 — 字段、必填/选填、布局、回复承诺
4. 落地页（有投放则抓，无则记缺口）— 与广告/检索词的信息匹配、单一 CTA

字段数、CTA 原文、信任信号必须来自已抓取正文。页面不可访问则记下状态原因，不编造。

### 竞品漏斗（≥3）

每个竞品记录：首页/产品页价值主张、询盘表字段数与 CTA 原文、弹窗或潜客捕获（无则「未观察到」）、流程页、伙伴/转介绍页、上市宣布。页面不可访问则记下原因并换下一个，不编造。

### 查询意图

把产品上下文的品类与目标市场代入下列意图，每条记下 URL、摘录、访问日期：

1. 该品类 B2B 询盘表最佳实践
2. B2B 制造落地页转化优化
3. 制造网站退出意向弹窗与潜客捕获
4. B2B 询盘回复时效与转化的公开基准
5. 制造供应商新客户 onboarding 与复购
6. B2B 制造报价阶段升级与交叉销售
7. 外贸制造产品上市策略
8. 制造转介绍计划与佣金结构公开做法
9. B2B 制造客户留存与流失预防
10. 目标市场该品类采购路径（当前或下一自然年）

结果不够时再补：展会日历、回复时效案例、样品政策公开页。仍用同一条搜索能力。

多页抓取需要隔离时 dispatch a subagent, else do it inline。

### 最低数据量

进入分析前至少备齐；达不到的写入缺口，不降低后项装成已完成。

- 本站：首页 + 产品页 + 询盘页已完整分析；落地页有则分析、无则缺口
- **3** 个竞品完整漏斗：落地/首页 → 表单 → CTA → 信任信号
- 询盘率、按字段数的表单完成、回复时效影响、复购率：有公开源则记下并标「行业参考值，实际以你的数据为准」；无则缺口
- 用户漏斗指标已采集，或显式写「用户数据未知」
- 目标市场买家行为、贸易条款（FOB/CIF 以产品上下文为准）、已出现渠道

### 校验

- 每个被分析页面须可访问；不可访问则换源并记原因
- 竞品数据来自已抓取正文，不靠假设
- 转化率、回复时长有来源；行业数字必须带「行业参考值，实际以你的数据为准」
- 禁止编造统计、竞品 URL 或未抓取页面的字段清单

## 分析

把每条发现映射到标准漏斗（入口名称以产品上下文已出现渠道为准，不默认某一平台）：

```
访问 → 落地/产品页 → 询盘 → 首次回复与资质判定
      → 报价/样品 → 订单 → 复购 → 转介绍
```

### 落地页

| 维度 | 标准 |
| --- | --- |
| 五秒测试 | 访客能说出你做什么、为何向你采购、你服务谁 |
| 价值主张 | 买家收益语言，不只规格语言 |
| 标题 | 能力、受众或结果三者至少落一 |
| CTA 层级 | 高意向 Request Quote → 中意向 Download Catalog → 低意向 View Portfolio |
| 信任信号 | 认证、工厂可信度、市场在场、项目组合 |
| 异议处理 | 定制能力、MOQ/交期、质量核验、运输风险 |
| 移动端 | 粘性 CTA、可点热区、可接受加载 |
| 信息匹配 | 落地页与广告创意 / 检索词一致 |

CTA 在首屏、产品细节、规格、页底重复出现。评分必须能指回已抓取段落。

### 询盘表单

每个字段都有成本；删非必要项。B2B 买家需要足够摩擦来资质判定，但不能多到放弃。即时通讯是否与表单并列，以目标市场为准。

| 档位 | 字段 | 适用 |
| --- | --- | --- |
| 最低可行 | Name + Email 或即时通讯 + Project Type | 移动端、冷流量 |
| 资质充分 | + Country + 规格/尺寸 + Quantity + Timeline | 桌面、暖流量 |
| 过度设计 | + Budget + Company size + Revenue | 挪到跟进，不放首表 |

布局：单列、移动优先；字段顺序 Contact → Country → Project Type → Specs → Dimensions/Quantity → Timeline → Notes；7 个字段以上才拆步；CTA 写行动加结果，不用空的 Submit。改表必须列出删/留/改的字段名。

### 弹窗与潜客捕获

外贸 B2B 可给的捕获物（不是试用）：目录 PDF、免费样品申请、快速报价/RFQ、工厂参观视频、展会邀请、新产品/新能力发布。

每个弹窗写清：类型、触发、定向、频次上限、标题、副文、CTA、拒绝文案、若有欧盟流量则合规勾选、移动端行为（每会话最多 1 个弹窗）。

冲突规则：即时通讯挂件常开；展会横幅首次展示时压制退出意向弹窗；关闭后 cookie 抑制 ≥14 天。

### 询盘流程

标准流：`访问 / 目录 / 展会 → 产品浏览 → 首次接触（表单/即时通讯/邮件/RFQ）→ 首次回复（方法默认：工作时间内 ≤2 小时）→ 资质与报价 → 样品提议 → 样品发出 → 样品认可 → 大货`。

按已出现渠道做摩擦：入口字段与移动端、渠道覆盖、回复速度、回复质量（点名产品、只问 1–2 个问题）、资质分层、样品桥、跟进节奏。

资质每维 1–5：预算匹配、时间线、项目类型、决策权、地理（对照产品上下文目标市场）、具体程度。档位：Hot → 当日详细报价；Warm → 2 小时内回复；Cool → 目录回复。

### 首单 onboarding

旅程：`首次询盘 → 报价 → 样品 → 样品质检 → 首单生产 → 生产更新 → 出运前检验 → 运输与追踪 → 到货确认 → 到货后跟进 → 复购`。

每阶段写：时机、渠道、内容类型、负责人。包含主动生产照片、请款前质检报告、全套运输文件加清关指引、到货后 3–5 天满意度核验。

样品政策：快递；收费样品可在大货抵扣；规格事先写清；交期明确。

### 升级与交叉销售

按产品上下文的品类字段映射升级路径：材质/等级、表面处理、厚度/尺寸、服务加项（包装、五金、检验、指南）、数量阶梯。禁止在 skill 里填具体牌号或产地。

报价结构模板（填用户真实规格，不把本段当交付物原文）：

```
BASE OPTION
Product: [standard spec] | Price: [observed or user-provided] | Total: [sum]

RECOMMENDED UPGRADE
Product: [premium spec]
Why: [one sentence citing project environment or buyer type]
Price: [observed or user-provided] | Total: [sum] ([premium %])

PROJECT NOTE
Environment: [from inquiry]
Recommendation: [technical advice]
```

不得删除基础选项。每条报价最多一个清晰升级建议。

### 上市策略

ORB：Owned / Rented / Borrowed，把买家导向自有关系。渠道名单以产品上下文为准。

| 上市类型 | 风险 | 渠道方向 | 关键约束 |
| --- | --- | --- | --- |
| 新产品/新工艺 | 低 | 邮件、即时通讯、已有目录页 | 样品就绪 |
| 新市场进入 | 中 | 职业社交、代理、本地协会 | 贸易条款、合规 |
| 展会 | 高（有截止日期） | 展前预约、胸卡录入 | 样品物流 |
| 网站上线 | 中 | 检索、协同引流 | 询盘流就绪 |
| 新能力发布 | 低–中 | 现有买家、定向信息 | 技术准确 |

三阶段：Pre-Launch（6–8 周：资产、买家名单、预热、物流）、Launch Week（宣布、页面上线、样品要约、预约）、Post-Launch（2–8 周：跟进、样品发出、漏斗追踪、复盘）。日期写成日历日或 T-xx / T-day / T+xx，禁止只写 Week 1。

### 转介绍与合作伙伴

计划类型：指定人转介绍、施工方转介绍、经销/代理招募、现有客户转介绍。

佣金仅作方法默认档（必须标「行业参考值，实际以你的数据为准」）：订单额 USD 10,000 以下 3%；10,000–50,000 为 4%；50,000 以上 5%；客户回款后再付。

无软件追踪：问 How did you hear about us?；保存介绍截图或邮件；表格记录日期、介绍人、客户、项目、金额、佣金。

激活：列出并给过往联系人打分 → 带着佣金结构外联 → 寄样品包与目录 → 月度跟进、记录介绍、7 日内打款 → 复盘并扩大。

### 留存与流失预防

无 SaaS 工具也可观察的流失信号：下单频率下降、连续 2 次以上询价未转、反复价格异议、只要规格/图纸、90 天以上无联系。

健康分：`Order Frequency × 0.35 + Order Value × 0.30 + Communication × 0.20 + Relationship × 0.15`。

| 分数 | 状态 | 动作 |
| --- | --- | --- |
| 80–100 | 健康 | 升级销售、邀请加入重点客户 |
| 60–79 | 需关注 | 主动核验 |
| 40–59 | 有风险 | 高层外联、查根因 |
| 0–39 | 危急 | 赢回序列 |

触点日历：到货后满意度；末单后 60 天管道核验；新上市定向信息；90 天无联系高层外联。

休眠 6 个月以上赢回：触点 1 价值；触点 2 点名过往订单 + 新能力；触点 3 直接询问/激励；触点 4 末次尝试或搁置。至少 4 步。

### 实验优先级

每个想法写：hypothesis、漏斗阶段、metric、priority（P0/P1/P2）、effort（Low/Medium/High）、expected_impact 并带来源。无来源的提升幅度写「未验证」，禁止编造百分点。

## 反模式

1. 套用试用开通、套餐升级、激活等 SaaS CRO 话术。
2. 不抓本站与竞品页面就给修改建议。
3. 忽略目标渠道的表单与页面限制。
4. 编造转化基准或回复时长，或不标行业参考值。
5. 目标市场需要即时通讯却完全不写入口策略。
6. 升级报价删掉基础选项。
7. 跟进只有客套问候。
8. 用 C 端网红带货或病毒 stunt 打 B2B 制造。
9. 一条报价推多个升级。
10. 任何交付物行的 `source` 为空。

## 可验证断言

交付物文末写 5–10 条。评审可用下列形状核对：

1. `funnel-optimization.md` 含 12 个必需章节（或显式缺口）
2. `funnel-redesign.xlsx`（或 json）含 7 张表且达到最低行数
3. 现状评估引用 ≥3 个本站不同页面 URL
4. 竞品对照 ≥3 行完整漏斗（落地 → 表单 → CTA → 信任）
5. 表单优化含 `field list`、`field order`、`required logic`、`mobile layout`
6. 留存含 health score 公式、流失信号、≥4 步赢回
7. Experiments ≥15 行（或主文档列出 ≥10 个实验），每条有 hypothesis、metric、priority、effort
8. 每张表 `source` 非空率为 100%
9. 行业基准均带「行业参考值，实际以你的数据为准」
10. 终稿不存在未替换的 `{{...}}` 占位；SaaS 术语（free trial、premium plan、activation）出现次数为 0
