# 竞品情报方法

读本文件前先确认 `SKILL.md` 已判定本 skill 适用。此处是查询意图、三层量尺、表结构与页纲要。

目录：

- [收集](#收集)
- [分析](#分析)
- [交付](#交付)
- [缺口与更新](#缺口与更新)
- [易错](#易错)

品类、目标市场、产地、替代方案名称一律取产品上下文对应字段，不在本文件填值。

## 收集

### 查询意图

用 Apify 搜索查证，覆盖下列意图；每条记下 URL、访问日期、摘录。证据够用或已写缺口即可停，不并列多家搜索引擎。

1. 品类 + manufacturer / supplier B2B
2. custom + 品类 + wholesale
3. 品类 + export + 目标市场
4. 品类 + 公开价格或单价（年份用当前，不编造历史价）
5. 品类 vs 替代方案（对上下文出现的每种替代各查一次）
6. 具名竞品 + 品类（对已知前 5 家重复）
7. 品类 + project case study / installation / tender / RFQ
8. 品类 + market trend
9. 品类 + MOQ
10. 目标渠道（以产品上下文为准）+ 品类
11. 品类 + OEM / ODM factory
12. 品类 + 目标市场买家会引用的权威页（案例、规范、招标）

### 抓取

需要原文时抓取指定 URL 的正文。优先：

- 前 3 家竞品域名的首页、产品、关于、认证或案例页
- 产品上下文若给出本方站点 URL：抓导航与品类页，只作对照，不把正文拷进 skill
- 目标渠道上的店铺或列表页
- 公开公司页、招聘页、动态页（有则记，无则缺口）
- 公开视频或社媒标题与说明（有则记，无则缺口）

用户已配置网页采集服务时，才用它抓公开页或动态页。未配置则只记录已抓到的 URL。Apify 修复与替代取证后仍不可得：停止并写缺口，不编造。

### 数据下限

硬门（达不到就写缺口，不降格成猜测）：

- 至少 5 家直接竞品：可访问域名、主要产品线
- 至少 3 家在目标渠道有价格、起订量或评价摘录
- 每家至少 1 个已验证可打开的产品页 URL

尽力项（有则写，无则缺口，不阻塞终稿）：

- 更多产品页 URL
- 公开视频或社媒
- 决策人公开资料（职称与所在行业，不写未核实的私人联系方式）

### 核验

- 每家必须有可访问域名；打不开的不进「已核验」名单。
- 价格只来自渠道列表、公开价目或 RFQ。
- 战斗卡每条话术能指回一条摘录。

## 分析

### 三层

1. **直接竞品**：同品类、出口或销售到同一目标市场的公司。
2. **替代方案**：买家会改用的材料、工艺或成品形态。
3. **采购路径**：从产品上下文的产地进口 vs 买家本地制造或本地供货。

### 对比维

**方案对比**（本品类 vs 替代）

| 维 | 看什么 |
| --- | --- |
| 耐久 | 寿命、磨损、环境耐受 |
| 设计余量 | 规格组合、表面/颜色、定制 |
| 安全与合规 | 相关法规与认证 |
| 维护 | 清洁、翻新、更换 |
| 全周期成本 | 采购 + 安装 + 维护（年限取上下文或标估计） |
| 安装 | 重量、固定、现场改动 |
| 可持续 | 回收、环境影响（有公开依据才写） |

**厂对厂**

| 维 | 看什么 |
| --- | --- |
| 规格广度 | 变体、特殊选项 |
| 设计能力 | 现货目录 vs 定制支持 |
| 起订量 | 标准 vs 定制下限 |
| 交期 | 确认订单后的生产日 |
| 质检 | 厂检、第三方、过程照片 |
| 沟通 | 响应、语言、项目管理 |
| 认证 | 上下文相关的体系与检测 |
| 包装运输 | 防损、物流选项 |
| 价格 | 可比规格下的单位价 |

**进口 vs 本地**

| 维 | 看什么 |
| --- | --- |
| 成本 | 贸易条款 + 关税 vs 本地价 |
| 质量 | 专厂 vs 综合作坊能力 |
| 品种 | 目录广度 vs 本地可做范围 |
| 交期 | 生产 + 运输 vs 本地周转 |
| 付款 | 信用证、电汇等 vs 本地习惯 |
| 风险 | 运输损伤、沟通、远程质检 |

贸易条款、起订量、认证等通用词按上下文原样使用。

### 战斗卡

对每家已核验直接竞品写内部卡，只填有摘录的字段：

1. 概况（所在地、规模信号、主市场）
2. 优势（诚实、有出处）
3. 弱点（具体、可核验）
4. 上表各维对照
5. 销售话术
6. 分场景怎么站位
7. 买家点名这家时的异议处理

### 建议页形态

内部战斗卡不公开。可公开的对比页只出纲要，完整 SEO 不在本 skill。

| 形态 | 检索意图 | 路径形状 | 漏斗 |
| --- | --- | --- | --- |
| 替代方案对比 | 在选项里做研究 | `/alternatives/<替代>-vs-<品类>` | 访问 → 询盘 |
| 场景选型 | 按用途研究 | `/guides/best-<品类>-for-<场景>` | 访问 → 询盘 |
| 战斗卡 | 内部销售 | 无公开 URL | 询盘 → 订单 |
| 采购路径对比 | 进口还是本地 | `/guides/import-<品类>-vs-local` | 询盘 → 订单 |

**替代对比页**：为何会考虑替代 → 本品类作为选项 → 逐维对比 → 谁该选哪边 → 项目例（仅上下文已有）→ 要样品或咨询。

**场景选型页**：该场景要看什么 → 选项排序 → 本品类为何合适（有证据）→ 项目例 → 选供应商标准 → 要项目咨询。

**采购路径页**：成本、质量、品种、交期、付款、风险 → 何时进口、何时本地 → 要报价对照。

对比页只到内容纲要（章节顺序与漏斗阶段）。建议 URL、meta 描述、目标检索词、FAQ 结构化数据等 SEO 规格走 `marketing-seo-audit`。公开页加摘要。相关对比页互链；产品页链到对应对比；可做枢纽页。常见问句可列入纲要，问句取真实检索词，不编造。

### 换商路径（写入采购路径页）

- 如何在不中断在制项目的前提下切换
- 打样流程
- 过渡期并行
- 规格移交（图纸、材料规格）
- 用样品对标质量

### 缺口分析

对手没覆盖的：产品规格/服务、区域或细分、交付能力。每条指回收集摘录。

### 买家角色

用产品上下文已有角色裁剪战斗卡与公开页，不在本文件发明角色名单。

## 交付

全部写到 `deliverables/marketing/01-foundation/`。策略与分析用简体中文。面客句子、URL、字段名、文件名按产品上下文；本仓库文件名保持英文。

### 主分析稿

`competitor-analysis.md`

每条建议引用收集摘录与 URL：

1. 竞争格局地图（只用地图上真实出现的公司）
2. 直接竞品深挖（≥5 家，有核验域名与具体数字或显式缺口）
3. 替代方案（有公开成本才写数字）
4. 采购路径（产地进口 vs 本地）
5. 优势与缺口
6. 行动建议 P0 / P1 / P2，指向可执行稿

### 表

`competitor-profiles.xlsx`：可从仓库 `templates/competitor-profiles.xlsx` 复制后填。至少 5 行。列：

```
company_name, domain, marketplace_store, price_tier, price_range_unit, moq,
product_lines, materials, certifications, markets, strengths, weaknesses,
linkedin_url, social_channels, source_urls
```

`marketplace_store` 填目标渠道上的店名或列表 URL，无则空并在缺口说明。`price_tier` 仅用 `budget` / `mid` / `premium`，且能指回摘录。`linkedin_url` 填公开公司页，无则空。每行 `source_urls` 非空。

## 缺口与更新

- **价格未知**：写「价格数据不可用 — 建议用同一规格向 3–5 家询价」。不编造。
- **方案对比缺公开数据**：可用行业公开区间，必须标「估计，待用户确认」，确认前不写入面客页。
- **几乎无竞品证据**：建议补目标渠道与行业展会公开信息；未核验的公司不进战斗卡。
- **季**：核对公开价格与新产品线。
- **买家点名新对手时**：加一张卡，不重写全部。
- **年**：全量刷新地图。

终稿禁止把未核验字段写成事实，禁止占位域名。缺的只进缺口栏。

## 易错

1. 编造对手价格。
2. 无摘录写「他们缺质量」。
3. 把官网口号当成已核验能力。
4. 无真实数据仍出战斗卡。
5. 隐瞒对手优势。
6. 占位 URL。
7. 抄对手文案。
8. 表或 JSON 无 `source_urls`。
9. 三层混写。
10. 话术不对应产品上下文的买家角色。
