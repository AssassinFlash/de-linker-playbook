# 冷邮件主题：变化 + 工作时刻 + 有界价值

条件：为冷首触写主题或 A/B 主题时读本文。

## 默认结构

一个强主题通常同时回答三个问题：

1. **为什么现在看**：当前政策、规则、供应或项目变化。
2. **为什么与我有关**：买家正在做的工作时刻，例如报价、下单、排班、调试。
3. **读下去能得到什么**：有明确边界的清单、判断或核对项。

模板：

```
[当前变化] + [买家工作时刻] + [有界结果]
[Current change] + [buyer moment] + [bounded result]
```

示例（正文必须真实交付三项核对）：

```
2026 60% cap: 3 checks before quoting small PV
```

若买家的服务区会实质缩小相关性，可把地点替换进主题：

```
Mainaschaff PV: 60% cap, 3 quote checks
```

地名不是装饰。只有当当地规则、电网运营方、市场结构或公开项目会改变正文内容时才使用；不能因为查到地址就制造“我一直在关注你”的假熟悉感。

## 其他可用结构

- **变化型**：`2026 cap: what changes before your next quote`
- **自我识别型**：`When project models change, what still needs checking?`
- **工作时刻型**：`Before the next small PV quote: 3 checks`

## 硬约束

- 政策或规则必须是本轮 Apify 已核验，并写清适用边界。
- 主题里的数字是承诺：正文必须真的交付对应数量的内容。
- 地点或项目若进入主题，必须能在正文说明它为什么改变读者的工作，不能只当装饰前缀。
- 主题不出现“领先、最好、一站式、合作机会”等自夸或空洞词。
- 不用虚假紧迫、假倒计时或无来源金额。
- 主题不是问题领取器：不能写“想了解吗”“要我发给你吗”。
- 低压主题默认少于 50 个字符；无法压缩时先删我方形容词，不删买家的工作时刻。

## A/B

- A：具体变化 + 工作时刻 + 数字。
- B：同一事实改成简短问题或结果句。
- 两个版本必须指向同一正文价值链，不能一封承诺清单、另一封承诺会议。
