# 成功邮件参考拆解

条件：用户提供一封“我愿意点开 / 愿意回复”的邮件，或点名一个公开邮件案例时，先读本文件再起草。参考样本是结构证据，不是原文素材。

## 先判断它是什么邮件

必须写清：

| 项 | 要回答的问题 |
| --- | --- |
| 关系 | 发件人与收件人是陌生、订阅、客户、试用用户，还是已有往来？ |
| 渠道 | 一对一开发信、群发 Newsletter、产品更新、交易通知还是 nurture？ |
| 目标 | 拉回复、点击、注册、购买、续费、教育还是通知？ |
| 读者状态 | 正在搜索、已有产品、被动接收、老客户还是流失用户？ |
| 证据 | 用户的主观反应、公开互动、发送方自报数据，还是可复核实验？ |

用户觉得“愿意点开”是重要的第一方反馈，但不能自动写成“该邮件转化率高”。发送方邮件里的自报数字仍是 claim，不是独立证明。

## 拆结构，不抄句子

按顺序标出：

1. **自我识别问题**：第一段是否让读者用现有经验判断“这说的是我”？
2. **问题/变化**：它用了什么已经发生的变化，而不是泛泛承诺？
3. **即时价值**：读者不回复、不点击时已经得到了什么？
4. **证明**：功能、工具数量、截图、案例、使用方式或可验证链接是什么？
5. **内容组织**：更新分几组，每组是否围绕一个具体工作结果？
6. **CTA**：它要求读者回复、点击、注册还是购买？压力来自哪里？
7. **关系前提**：这封邮件为什么可以提出这个 CTA？换到陌生买家是否仍然成立？

## 迁移表

| 机制 | 为什么可能有效 | 转到当前买家还成立吗 | 风险 |
| --- | --- | --- | --- |
|  |  |  |  |

只能迁移机制和顺序，不迁移以下内容：

- 不得复制原文、独特句式、品牌口号或个人语气；
- 不得把对方的受众规模、工具数量、结果率当作我方证据；
- 不得照搬多 CTA、长 Newsletter、图片和促销区到一对一冷邮件；
- 不得假设陌生买家拥有与订阅用户相同的信任和上下文。

## 用于当前冷邮件的最低输出

- `reference_sample`：来源与日期；
- `relationship_context`：为什么该样本的 CTA 能被接受；
- `transferable_structure`：最多 3 条；
- `non_transferable_parts`：至少 2 条；
- `new_value_delivered`：当前收件人无需回复即可得到什么；
- `optional_relation_line`：与当前项目相关时再联系的自然条件。

样本分析和新邮件正文分开保存；不要把参考邮件原文贴进交付物。
