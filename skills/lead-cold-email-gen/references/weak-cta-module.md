# 低压弱 CTA

条件：模式为 Low-Pressure 或 Both 时读本文。执行顺序与完成条件以 `SKILL.md` 为准。

CTA 必须接到正文的痛点或洞察，像自然下一步，而不是另加一句约会议。禁用「Would you be open to a call?」及同义句。

所承诺的材料必须是已有交付物，或本轮能立刻写出的短件。不能承诺未做的竞品拆解、未持有的基准或未核实的合规摘要。

## 先给，再问

对未互动买家的冷首触，默认是 **Value-First**：价值必须先出现在邮件里，不能让回复成为领取价值的前提。

- **无 CTA（默认可选）**：正文直接给一条判断、一项政策影响或三点核对，写完就停。买家愿意时自己回复。
- **自取价值**：把已经做好的清单、链接或短报告直接放进邮件；不要求买家先同意接收。
- **先给再问**：先给出可立即使用的 2–3 点内容，再问一个与这些内容有关的可选问题。
- **条件式联系**：给完内容后，可写「If one of these checks matches a current project, feel free to reply.」不要写「No need to reply」；这会让邮件显得刻意或防御。

反模式：`Want me to send it?`、`Should I send you the checklist?`、`Reply and I'll share...`。这些话仍把价值扣在回复之后，不算低压力首触。只有在买家已经主动询问、或双方已有往来时，才可提出发送完整版。也不要默认写「No need to reply」；若保留最后一句话，用“与当前项目有关时再联系我”这种自然条件。

## 条件式相关收尾（Conditional Relevance Close）

这是低压首触默认的收尾方式。低压感不来自客套话，而来自顺序和权力关系：

1. 正文已经把有价值的内容交付给读者，不要求先回复。
2. 发信人已经给出自己的判断或使用顺序，保持专家姿态。
3. 最后只给一句与当前工作相关的可选入口，回复不是领取条件。

**当前已批准示例**：

`Those are the three checks I would use before a quote. The first two decide what you can safely promise the customer; the third decides what you commit to on storage. If one of these checks matches a current project, feel free to reply.`

这不是固定台词。可复用的是下面这个变体语法：

`If + [买家当前工作条件] + [低门槛继续方式].`

**变体轴**：

| 轴 | 可选表达 | 作用 |
| --- | --- | --- |
| 关联条件 | `one of these checks matches a current project` / `this is relevant to a live quote` / `this touches something you’re working on now` | 说明为什么值得继续，不要求对方证明需求 |
| 继续方式 | `feel free to reply` / `happy to continue the conversation` / `let me know` / `happy to compare notes` | 给一个轻量动作，不追加任务 |
| 具体程度 | 通用 `these checks` / 具体 `the 60% cap or storage sizing` | 越具体越像当前工作，越通用越像模板 |

**L-0002 可用变体（本次定稿仍用已批准原句）**：

1. `If one of these checks matches a current project, feel free to reply.`
2. `If this is relevant to a live quote, I’m happy to continue the conversation.`
3. `If a current project is already affected by the 60% cap, feel free to reply.`
4. `If you’re working through one of these now, let me know.`
5. `If this is on your desk at the moment, happy to compare notes.`

变体只换表达，不改变关系结构。不要为了“有变化”而把一句邀请扩成问题、三选一、会议请求或多个 CTA。

为什么有效：

- **读者保有自主权**：是否回信由“当前项目是否相关”决定，不由发信人的催促决定。
- **不制造额外作业**：读者不需要选择题、写经验或先交型号；觉得相关时才回。
- **价值已经到手**：即使不回复，正文仍然有用，因此邀请不带交换条件。
- **顺势把话交给对方**：前面是发信人的判断，最后一句把对话入口留给买家，没有突然变成问卷。
- **允许沉默**：不回复不代表拒绝，也不触发下一句追问。

**必须遵守**：

- 条件句前必须有价值交付和至少一句工作阶段/使用判断。
- 只出现一个入口；不加第二个问题、三选一、会议邀请或资料索取。
- 不复述前文，不写 `No need to reply`，不写 `Want me to send it?`。
- 操作者给出最终原句时逐字保留，不即兴替换成“更互动”的 CTA。

## 收尾铺垫

价值清单不能突然停住，再接一句模板式“有关再联系”。在发信人和陌生买家之间，收尾先走两段，再决定要不要留一个条件式入口：

1. **内容边界**：用一句短句明确“以上就是要交付的主内容”，让读者的注意力知道正文已经收束。
2. **价值落点**：说明这几项分别影响报价、下单、调试等工作阶段，并给出你的使用顺序或判断。不要只复述清单。
3. **条件式入口**：最后用一句把正文与读者的当前项目相连，例如 `If one of these checks matches a current project, feel free to reply.` 它只是可选入口，不要求对方交出资料，也不把前面的判断再解释一次。

一个冷首触只需要一个回复入口。已订阅的产品更新 Newsletter 可以用多个 CTA，是因为读者已经认识发件人并主动订阅；不能把这个结构直接搬到陌生邮件。

收尾检查：读完最后两段，读者应当感到“内容已经说完，而且我知道该拿它做什么”。最后只写一个与正文相关的条件，例如 `If one of these checks matches a current project, feel free to reply.`。不要用“如果项目适用，我会先做前两项”这种句子复述作者刚说过的判断。操作者已经给出最终原句时，逐字保留，不另造问题。

## 格式 1：情境微要约

**何时：** 已先给出一个具体判断，且还能再给一份相关短件。

**句式：** 点名该情境 + 提出一份小而具体的材料 + 说明不要求对方改系统或开会。

`Since [已核验工作流], here are the two points worth checking first: 1... 2... If one of these matches a current project, feel free to reply.`

**为何：** 对方先拿到内容，再决定要不要回应，不必用回复换取第一份价值；最后一句只是开放的关联入口，不是强制交换。

## 格式 2：好奇心

**何时：** 确有可分享的对照、基准或时点变化，且来源已在「来源」表。

**句式：** 点名那份已有材料 + 邀请看一眼，不夸大。

`Just finished [有来源的对照或基准]. Want a quick peek?`

对照对象必须来自 `deliverables/lead/04-market/` 或本轮已抓取页。禁止虚构「对你们两家竞品做了基准」。无来源百分比不写进 CTA。

**为何：** 回信门槛是「发来看看」，不是权衡是否开会。

## 格式 3：买家阶段多选项

**何时：** 不确定对方处在评估、比选还是已在列供应商。

**句式：** 2–3 个不同承诺量的选项，让对方自选。

`Happy to send [低承诺材料] if you're still evaluating — or [中承诺材料] if you're already mapping vendors.`

选项必须都是本轮能交付的。任意一个选择都算回复。

**为何：** 把是/否开会换成三选一的低摩擦动作。

## 格式 4：破格

**何时：** 收件人冷信很多、模式识别强（资深采购、VP）。

**句式：** 打破「约会议」预期，用一个不卖产品的具体邀请。仍须可兑现，不用无来源的战胜百分比或对赌数字。

`Most [角色] ask us about price first. The ones who stay ask about [出乎意料但真实的因素]. Which camp are you in?`

**为何：** 打断自动删除。不可兑现的机智句不要用。

## 结构四式

同一批次里轮换，不要五封同一骨架：

1. **Pain → Fix → CTA** — 问题 → 一条 USP → 下一步
2. **Trigger → Insight → Value delivered** — 已核验事件 → 含义 → 直接给出可用内容（可选再留问题）
3. **Stat → Reframe → Specific help** — 有来源的数字 → 含义翻面 → 针对性帮助；没有数字就改用第 1 式
4. **Micro-story → Takeaway → CTA** — 产品上下文或已抓取案例里的短故事 → 教训 → 对应要约；无案例不编

## A/B

每封可测三条轴，各写进主题 A/B 或 Performance Notes，不要另造一封假信凑数：

- 主题：洞察 vs 好奇
- CTA 力度：直接请求 vs 暗示价值
- CTA 语序：先要约 vs 先问句

低压主题的具体构造见 `subject-line-patterns.md`。优先写清当前变化、买家工作时刻和有限价值；不要用模糊好奇代替真实相关性。

## 收束句式

只用在边界句、价值落点和发信人立场之后；一句，不堆：

- 说一声就发
- 不急，觉得可能有用
- 发了也无附加条件

落款仍走 `SKILL.md`：上下文没有人名则 `[待补充]`。
