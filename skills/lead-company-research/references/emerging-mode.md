## 何时跑

- 用户只要新兴名单：本文件 + `SKILL.md` 步骤，产出只写新兴文件。硬依赖是已批准的标准名单（`lead-company-research` → 本变体）；未批准且无 `user_waiver` → 停。有 waiver 时仍排除知名长期在位企业，并尽可能对照磁盘上已有的标准名单去重。
- 用户两种都要：先按 `SKILL.md` 写完标准名单，同一入口接着写新兴名单。
- 未点名新兴：不要自动再产一份新兴名单。

## 额外约束

在三信息块之外，入选公司还必须：

1. **员工数低于 200**，数字来自已抓取的公开页。员工数「未在来源出现」→ 不能算作已核验新兴，不入选。
2. **不是行业里人人知道的长期在位企业**（长期上市巨头、全国默认品牌）。标准模式可以收匹配 ICP 的较大公司；新兴模式不收。
3. **有增长信号**（下一节），带 URL 与日期。
4. **与标准名单零重叠**（下一节）。
5. 仍然是可核验买家：官网可达、本轮搜索命中、符合选定 ICP 与地域。

新兴 ≠ 查无资料。没有任何可抓页面或增长证据的公司，是不可核验，不是新兴。

## 增长信号

至少一条，且能打开来源页。可接受类型：

- 融资或所有权变动（公告、监管披露）
- 招聘明显扩张（职业页或招聘启事的规模变化）
- 新产品或产线发布
- 进入新市场或新工厂/办事处

只写「高增长」「有潜力」不算。把信号原文短摘 + URL 写入 `growth_signals`。`founded_year` 有公开成立年就写，没有则「未在来源出现」，不因此单独取消资格。

## 与标准名单

对照 `deliverables/lead/02-companies/target-companies.md` 与 `target-companies.xlsx`（或 csv）的 `company_name` 与 `domain`。任一相同即剔除。标准名单不存在且用户未 waiver：停。标准名单存在但未批准：仍先去重，是否继续由硬依赖规则决定。

标准模式的「优先成长期」不是新兴模式。标准名单允许混入匹配 ICP 的较大买方；新兴名单更严，且必须是另一份文件。

## 产出

主文件 `deliverables/lead/02-companies/emerging-companies.md`，结构同标准稿，抬头 `mode: emerging`，每家三块之后加：

```markdown
#### 成立年份
#### 增长信号
（类型 + 摘录 + URL + 日期）
```

表：`emerging-companies.xlsx`（或 csv）。标准 14 列之外加 `founded_year, growth_signals`。

目标 10 行；不足写实数与缺口，不拿标准名单里的公司改写充数，不编造员工数。

## 质检

- [ ] 每家员工数有来源且低于 200
- [ ] 每家至少一条带 URL 的增长信号
- [ ] 无标准名单域名或公司名重复
- [ ] 无长期在位巨头充新兴
- [ ] 三块与域名规则与标准模式相同
- [ ] 未把本变体写成另一个 skill 名或入口
